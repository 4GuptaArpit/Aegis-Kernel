# Aegis-Kernel UI-UX Architecture & Design System

## Executive Summary
Aegis-Kernel is an autonomous GPU invariant and kernel-proving workbench engineered for the Nebius x NVIDIA Global AI Hackathon '26. It demonstrates a closed-loop adversary collider: Nemotron Red Adversary fuzzer versus Nemotron Blue Triton healer on NVIDIA Hopper H100 SXM5 and Blackwell B200 hardware.

This architecture specification delivers an elite cyber-physical supercomputing experience. It eliminates visual clutter, prevents component collisions, provides hardware authenticity down to SIMT thread lanes and PTX predication registers, and exposes an interactive proving ground.

## 1. Open Questions & Architectural Resolutions

| # | Question / Ambiguity | First-Principles Analysis & Impact | Stated Resolution / Implementation Choice |
|---|----------------------|------------------------------------|--------------------------------------------|
| **Q1** | **Information Density vs. Congestion**: How can an operator monitor 8+ complex instruments (132 SM die, 32-thread warps, AST diff, PTX ISA, memory waterfall, Nsight HUD, terminal) without visual crowding? | Cramming all instruments onto a single scrolling viewport forces cramped 600px heights, overlapping canvases, and high cognitive load. Splitting completely into disconnected tabs destroys real-time situational awareness during automated collider runs. | **Hierarchical Dual-Mode Spatial Architecture**: A persistent executive command cockpit on top paired with a 4-stage primary viewport (`01 Red vs Blue Collider`, `02 132-SM Die & Warp Matrix`, `03 AST Diff & PTX Disassembly`, `04 Nsight Profiler & Memory Waterfall`), backed by an ambient status telemetry bus that reflects pipeline state across all stages. |
| **Q2** | **Aesthetic Identity**: How to avoid generic dark-mode SaaS templates while preventing unreadable sci-fi glow? | Generic cards use low-contrast grays (`#1e293b`), default rounded borders, and flat dashboards. Over-the-top sci-fi obscures data readability with bloom shaders and illegible fonts. | **Obsidian-Substrate Cyber-Physical Palette**: Foundation of deep obsidian void (`#03060D`) and high-density glass surfaces (`rgba(8, 14, 26, 0.85)`). High-energy laser accents are strictly functional: NVIDIA Emerald (`#00FF88`) for verified invariants, Plasma Coral (`#FF0055`) for memory bus traps/crashes, Cyan (`#00F0FF`) for HBM3e/L2 crossbars, and Amber (`#FFB800`) for tail-warp divergence. Typography pairs Plus Jakarta Sans with JetBrains Mono. |
| **Q3** | **Hardware Authenticity**: What level of GPU architecture fidelity is required to impress NVIDIA and Nebius kernel engineers? | Generic mockups show arbitrary grid squares and fake progress bars. Real GPU kernel engineers look for exact hardware constraints: 132 SMs across 8 GPCs on GH100, 32 threads per warp, `@p0` hardware predication flags, coalesced 128-bit vector loads, and 4-tier memory hierarchy timings. | **Microarchitectural Fidelity**: The Die view models all 132 SMs individually with GPC cluster grouping and interactive SM selection. The Warp view models all 32 threads with individual lane state, memory address offsets (`0x7F4E82XX`), `@p0` hardware predicate evaluations, and instruction-level PTX disassembly. |
| **Q4** | **Parameter Interactivity**: What controls must be interactive during proving runs? | A static dashboard fails to demonstrate dynamic vulnerability discovery. The vulnerability depends on ragged sequence lengths not divisible by 32. | **Live Scrubber & Target Switcher**: Real-time sequence length scrubber (32 to 2048 tokens) displaying ragged tail thread divergence (`seqLen % 32 != 0`), hardware target switcher (Hopper H100 SXM5, Ada L40S, Blackwell B200), and workload selector (`swiglu`, `rmsnorm`, `softmax`). |

### 2.2 Typography Hierarchy
- **Header & Interface Display**: `Plus Jakarta Sans` (Weights: 500, 600, 700, 800) with `-0.02em` letter tracking.
- **Microarchitectural & Code Telemetry**: `JetBrains Mono` (Weights: 400, 500, 700) with tabular numeric alignment (`tnum`).
- **Scale**:
  - Hero Metrics / Speedup: `2.5rem` (40px), font-extrabold, monospace, glow filter.
  - Section Headers: `0.95rem` (15.2px), 700 uppercase, monospace, letter-spacing `0.08em`.
  - Telemetry Labels: `0.72rem` (11.5px), 600 uppercase, letter-spacing `0.05em`.
  - Disassembly & Addresses: `0.80rem` (12.8px), monospace, regular/medium.

### 2.3 Spatial Grid & Layout Rhythm
- **Maximum Width**: `1600px` centered with `24px` gutter breathing room.
- **Vertical Rhythm**: `16px` gap between major command surfaces and stage views.
- **Card Padding**: Inner padding of `16px` to `20px` to guarantee elements never touch container edges.
- **Micro-Borders & Scanlines**: Sub-pixel `1px` borders with `backdrop-filter: blur(16px)` and subtle linear scanlines at `32px` intervals.

### 3.1 Stage 01: Red vs Blue Collider & Mic-Drop Delta
- **Red Adversary Chamber**: Displays Nemotron 3 Ultra synthesizing ragged tensor workloads with pathological boundary offsets (`seq_len=1023`). Real-time hex dump of unaligned memory access triggering illegal address dereference (`0x7F4E8240`).
- **Central Collision Core**: Visual energy reactor indicating state (`IDLE`, `COMBAT`, `COLLISION`, `HEALED`). Features an animated concentric photon ring.
- **Blue Defense Chamber**: Displays Nemotron 70B Triton synthesising guarded block loads with zero-penalty predication masks (`mask = offs < seq_len`).
- **Mic-Drop Speedup Delta Card**: Large format indicator contrasting baseline unmasked PyTorch (54.3 μs, 1.00x) against Aegis Triton (23.1 μs, 2.35x speedup), proving zero runtime overhead for safety.
- **Terminal Window**: High-speed monospace streaming log with color-coded severity tags (`[INIT]`, `[TAVILY]`, `[CRIMSON EXPLOIT]`, `[NEMOTRON BLUE]`, `[FORMAL INVARIANT]`).

### 3.2 Stage 02: 132-SM Die Topology & 32-Warp Matrix
- **Hopper GH100 Silicon Die**:
  - Models the full 132 Streaming Multiprocessors arranged into 8 GPCs (Graphics Processing Clusters).
  - Interleaved HBM3e memory controllers (4 high-speed channels @ 834 GB/s each) linked by the 50 MB L2 crossbar cache highway.
  - Interactive SM selection: Clicking any SM updates real-time telemetry; SM 14 is highlighted with a crimson pulse during memory fault stages and emerald upon patch deployment.
- **32-Warp SIMT Execution Matrix**:
  - Detailed inspection of Warp 0 running on the selected SM.
  - Displays all 32 thread lanes (Lanes 0–31).
  - Interactive lane selector: Clicking a lane inspects register values, target addresses, hardware predicate register state (`@p0`), and PTX instruction.
  - Interactive Mode Toggle: Allows instantaneous comparison between "Unprotected CUDA (Crash)" and "Aegis Hardened Triton (Immune)".
  - Visual thread lane states:
    - Lanes 0–16: Coalesced 32-bit Half2 vector load (active emerald glow).
    - Lanes 17–31 (Vulnerable): Hardware MMU bus panic pulse (coral alert glow).
    - Lanes 17–31 (Hardened): Hardware-predicated `@p0 == 0`, zero clock penalty, invariant 0.0 zero-register suppression (azure shield glow).

### 3.3 Stage 03: AST Diff & PTX Disassembly Inspector
- **Dual-View Code Inspector**:
  - High-level view: Unprotected CUDA C++ pointer math (`reinterpret_cast<const half2*>`) vs. Triton block pointer masking (`tl.load(..., mask=mask_m, other=0.0)`).
  - Assembly view: Hopper PTX ISA v8.4 disassembly showing raw unpredicated global load (`ld.global.v2.f16`) vs hardware predicate setup and load (`setp.lt.u32 %p0`, `@p0 ld.global.nc.v2.f16`).

### 3.4 Stage 04: Nsight Profiler & 4-Tier Memory Waterfall

  - 6 hardware telemetry gauges: SM Occupancy (100.0%), Tensor Core Engine (418.5 TFLOPS), HBM3e Bus Saturation (2.84 TB/s), SM SRAM Allocation (184 KB / 228 KB), Warp Divergence (0.0%), PTX Register Pressure (32 Regs/Thread).

## 4. Hardware Authenticity & Microarchitectural Spec

The architecture embeds authentic NVIDIA Hopper GH100 microarchitectural specifications:

1. **Streaming Multiprocessors**: 132 SMs across 8 GPCs fabricated on TSMC 4N process.
2. **SIMT Warp Execution**: 32 threads per warp executing lockstep SIMT instructions.
3. **Hardware Predication**: Zero-overhead `@p0` predicate register assignment, bypassing branch divergence penalties.
4. **Memory Hierarchy**:
   - 80 GB HBM3e global memory delivering 3.35 TB/s peak bandwidth.
   - 50 MB high-speed L2 crossbar cache delivering 12.0 TB/s bandwidth.
   - 228 KB configurable shared memory/SRAM per SM (Tensor Memory Accelerator enabled).
   - 64K 32-bit register file per SM sustaining single-cycle access.
5. **Nsight Compute Telemetry**: Saturated roofline compute at 418.5 TFLOPS FP16/BF16 tensor performance.
