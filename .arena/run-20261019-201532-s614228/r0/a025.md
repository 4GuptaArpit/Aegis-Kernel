## 1. Executive Summary & Design Vision

Aegis-Kernel is an enterprise-grade autonomous GPU kernel proving workbench designed to demonstrate closed-loop invariant discovery, red-teaming fuzzing, and autonomous synthesis of hardened Triton kernels across NVIDIA Hopper GH100 and Blackwell B200 architectures. 

The primary UX objective is eliminating visual congestion while maximizing scientific credibility, telemetry depth, and aesthetic impact ("GA-GA" factor). Rather than overwhelming the user with a monolithic dashboard of competing widgets, Aegis-Kernel introduces a **Hierarchical Tri-Tier Spatial Architecture**:

```
+----------------------------------------------------------------------------------------------------+
|  TIER 1: GLOBAL EXECUTIVE COMMAND COCKPIT (Sticky Top Bar - 68px)                                   |
|  [Brand // Logo] | [Hardware Target Dropdown] | [Workload Selector] | [Sequence Scrubber] | [RUN]  |
+----------------------------------------------------------------------------------------------------+
|  TIER 2: DYNAMIC STAGE PIPELINE & MODE ORCHESTRATOR (Sub-Header - 48px)                           |
|  [01 Red vs Blue] [02 Silicon Die & Warps] [03 AST & PTX Diff] [04 Nsight & Waterfall] [Overview]  |
+----------------------------------------------------------------------------------------------------+

|                                                                                                    |

|   |   authentic hardware telemetry, live interactive shaders, and zero visual overlap)        |   |

+----------------------------------------------------------------------------------------------------+
```

## 2. Open Questions & Stated Assumptions

| # | Question / Requirement Ambiguity | Architectural Resolution & Stated Assumption |
|---|---|---|
| **Q1** | How should the user switch between deep isolated stage inspection and a unified executive view without re-introducing congestion? | Introduce a 5th navigation mode: **`00 Executive Overview` (Bento Grid)** alongside the 4 deep-dive stages. The Overview uses strict 24px gutters, macro KPI telemetry, and high-level miniature die previews. Deep-dive stages retain 100% focused breathing space. |
| **Q2** | How to handle multi-GPU targets (Hopper H100 vs Blackwell B200) when Hopper has 132 SMs and Blackwell has 148/160 SMs? | The die topology component dynamically recalculates its grid layout matrix, memory bandwidth counters (3.35 TB/s HBM3 vs 8.0 TB/s HBM3e), and cache hierarchies based on the active hardware target selected in the Executive Command Bar. |
| **Q3** | How should rag-sequence-length tail effects (@p0 predication) be made tangible to judges in real-time? | The Sequence Scrubber ($seq\_len \in [1, 4096]$) dynamically highlights inactive warp lanes in crimson and active lanes in laser emerald. Threads with lane IDs $\ge (seq\_len \pmod{32})$ explicitly display hardware predication flag `@p0 = 0` (inactive) vs `@p0 = 1` (active). |
| **Q4** | How to balance terminal logging with hardware visualizers without fighting for vertical height? | Provide an interactive collapsible/dockable **HUD Drawer** for the Terminal Window with a persistent one-line streaming status ticker and an expand/minimize toggle ($H_{collapsed} = 38\text{px}$, $H_{expanded} = 280\text{px}$). |

## 3. Working Backwards: The Finished Experience

### 3.1 The User's Visual & Interactive Journey
1. **Immediate Visual Stunner (0.0s - 1.5s)**:
   The application opens into an obsidian void (`#03060D`) layered with subtle quantum hex-grid scanlines and low-frequency radial ambient emerald glows (`rgba(0, 255, 136, 0.04)`). The typography pairs **Plus Jakarta Sans** for executive clarity with **JetBrains Mono** for hardware-accurate register and telemetry readouts.
2. **Contextual Hardware Priming (1.5s - 5.0s)**:
   Judges observe the sticky Executive Command Bar. The target is set to `NVIDIA Hopper H100 SXM5 (80GB · SM_90a · 3.35 TB/s)`. The workload defaults to `Fused SwiGLU (LLaMA-3 / Mistral)`. The Sequence Length Scrubber is primed at `1023 tokens`—a deliberate non-multiple of 32 that triggers tail-warp divergence.
3. **Engaging the Proving Ground (Clicking [EXECUTE PROVING LOOP])**:
   - **Tavily Hardware Recon**: Queries web and ISA databases for SM_90a memory alignment specs. Stage indicator pulses amber.
   - **Crimson Fuzzing Strike**: Red Adversary (Nemotron 3 Ultra) detects unmasked boundary access at offset `1024`. SM 14 trips `SIGSEGV 139` with an Out-of-Bounds memory violation. SM 14 on the die pulses high-voltage plasma coral (`#FF0055`).
   - **Nemotron Blue Autonomous Healing**: Generates a hardened Triton kernel utilizing block-level boundary masking: `tl.load(ptr, mask=offsets < seq_len)`.
   - **Dual Verification & Attestation**: Compiles to PTX with `@p0` hardware predication. Nsight telemetry logs **$2.35\times$ Speedup**, **418.5 TFLOPS**, and registers a cryptographic SHA-256 invariant attestation: `0x7f56b9fe02089399`.

## 4. Hardware-Authentic Technical Foundations

### 4.1 NVIDIA GH100 Silicon Die Architecture (132 SM Matrix)
- **Topological Layout**: 8 Graphic Processing Clusters (GPCs), 66 Texture Processing Clusters (TPCs), yielding exactly **132 Streaming Multiprocessors (SMs)**.
- **Micro-Architecture Simulation**: Each SM visualizes:
  - 4 Processing Blocks (Sub-Cores) with independent Warp Schedulers.
  - 128KB unified L1 Data Cache / Shared Memory per SM.
  - Fourth-generation Tensor Cores supporting FP8 and Transformer Engine (TE).
- **Interactive Die Interrogation**: Clicking any individual SM (e.g., SM 14) dynamically binds the 32-Warp Execution Matrix and L1/Shared Memory telemetry to that specific physical core.

### 4.2 SIMT 32-Thread Warp Matrix & `@p0` Hardware Predication
- **SIMT Lane Visualization**: Warp 0 renders exactly 32 discrete thread lanes (Lane 00 through Lane 31).
- **Predication Logic**:
  $$\text{Predication Flag } @p0 = \begin{cases} 1 & \text{if } \text{ThreadIdx.x} < (seq\_len \pmod{32}) \\ 0 & \text{if } \text{ThreadIdx.x} \ge (seq\_len \pmod{32}) \end{cases}$$
- **Color Coding**: Active threads display neon emerald (`#00FF88`), while predicated-off tail lanes show inactive obsidian-crimson (`rgba(255, 0, 85, 0.25)`) with an overt `@p0=0` badge.

### 4.3 4-Tier Memory Hierarchy Waterfall
- **Tier 1 (HBM3e / Device Memory)**: 80GB capacity, $3,350\text{ GB/s}$ sustained bandwidth.
- **Tier 2 (L2 Crossbar Cache)**: 50MB shared L2 cache, $5.12\text{ TB/s}$ bandwidth.
- **Tier 3 (Shared Memory / SRAM)**: 228KB per SM, $18.4\text{ TB/s}$ aggregate bandwidth.
- **Tier 4 (Register File & Tensor Cores)**: 65,536 32-bit registers per SM ($33.2\text{ TB/s}$ peak feed).

### 5.2 Layout Blueprint & Stage Decoupling

## 7. Interactive Proving Controls & Dynamic Parameter Scrubber

The Executive Command Bar features the **Dynamic Sequence Length Scrubber**, engineered with real-time feedback on warp alignment:

$$\text{Ragged Boundary Condition: } seq\_len \not\equiv 0 \pmod{32}$$

When `seqLen` is adjusted:
1. The badge dynamically shifts to warn: `RAGGED BOUNDARY: TAIL OF N THREADS ACTIVE`.
2. The SIMT Warp Visualizer animates lanes $0 \dots (N-1)$ with active emerald pulse and lanes $N \dots 31$ with predication deactivation (`@p0 = 0`).
3. Audio feedback ticks with precise micro-pitches on slider increment.
