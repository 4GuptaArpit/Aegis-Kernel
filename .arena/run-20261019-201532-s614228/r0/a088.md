# Aegis-Kernel UI-UX Architecture & Design System

## Executive Summary
Aegis-Kernel is a hardware-native autonomous GPU invariant and kernel proving workbench engineered for NVIDIA Hopper H100 and Blackwell B200 architectures. It transforms high-dimensional GPU microarchitecture data (132 Streaming Multiprocessors, SIMT 32-thread warps, `@p0` hardware predication, 4-tier memory hierarchies, and 100KHz Nsight telemetry) into a zero-congestion spatial command cockpit. By decoupling dense telemetry into a 4-stage reactive spatial workbench, Aegis-Kernel eliminates visual fatigue, provides intuitive parameter manipulation via dynamic sequence scrubbers and hardware target selectors, and highlights the algorithmic collision between the Nemotron Red Adversary fuzzer and Nemotron Blue Triton healer.

## 1. Architectural Principles & First-Principles Decomposition

### 1.1 The Core Problem & Elimination of Congestion
Generic AI hackathon interfaces suffer from "dashboard sprawl": stacking dozens of uncoordinated cards, dense telemetry charts, and terminal logs simultaneously into a single viewport. In high-performance GPU engineering, this approach fails because developers and judges cannot discern cause and effect between mathematical invariant violations and silicon hardware states.

Aegis-Kernel solves this through **Spatial Stage Decoupling**:
- **Orthogonal State Isolation**: Telemetry, execution matrices, diff inspectors, and collision arenas never compete for the same visual pixels.
- **Contextual Anchoring**: The Executive Command Cockpit stays pinned at the top (under 120px height budget), providing permanent control over target hardware, sequence length, and execution lifecycle.
- **Negative Space as Information Architecture**: 24px-32px margins between primary instruments provide visual breathing room, allowing high-contrast laser indicators to draw focus immediately to anomalies (e.g., out-of-bounds predicates on Warp 0).

### 1.2 Hardware Authenticity Mapping
To satisfy NVIDIA and Nebius systems architects, every UI component maps 1:1 to physical silicon structures:
1. **Hopper GH100 Full Die Topology**: 132 SMs arranged across 8 Graphics Processing Clusters (GPCs). SM 14 is highlighted dynamically when Red fuzzer introduces out-of-bounds memory accesses.
2. **SIMT Warp Execution Matrix**: 32 distinct thread lanes (`lane_id` 0 to 31). Unmasked threads appear in volatile coral (`#FF0055`), while `@p0` predicated safe masks glow in NVIDIA emerald (`#00FF88`).
3. **4-Tier Memory Waterfall**: Visualizes data traversal and throughput bottlenecks from HBM3e (3.35 TB/s) down to L2 Cache (50 MB), Distributed Shared Memory (SRAM / 228 KB per SM), and Tensor Core registers.
4. **Nsight Real-Time Telemetry**: Real-time tracking of Tensor Core Utilization, SM Occupancy, Warp Divergence Penalty, and Memory Bus Saturation.

### Stage 01: Red vs Blue Collider & Mic-Drop Delta
- **RedBlueArena**: Particle collision visualizer contrasting Nemotron-3 Ultra (Red Fuzzer) generating boundary mutations against Nemotron-70B (Blue Triton Healer) synthesizing formal `@p0` predicates.
- **MicDropDelta**: Quantified benchmark comparison displaying a **2.35x speedup** over unhardened CUDA, memory safety guarantee (`0` illegal address traps), and strict invariant convergence.
- **VerificationImpact**: Verification badges, attestation certificate generator, and direct GitHub pull request export.
- **Streaming Terminal**: Monospaced real-time trace log with auto-scroll and clear capabilities.

### Stage 02: 132-SM Die & 32-Warp Execution Matrix
- **HopperDieTopology**: Interactive SVG grid rendering all 132 SM cores. Users can inspect any individual SM, observing its thermal profile, active warp count, and fault indicators.
- **WarpVisualizer**: Explicit breakdown of Warp 0 (Threads 0-31). When ragged sequence length (`seqLen % 32 != 0`) is applied, tail lanes display hardware divergence and predication masking in real time.
- **Telemetry HUD**: Immediate readout of Warp Divergence Penalty (drops from 18.4% to 0.0% upon healing).

### Stage 03: AST Diff & PTX Disassembly
- **Side-by-Side Unified Code Inspector**: Left pane displays vulnerable unmasked CUDA C++ kernel; right pane displays hardened Triton Python kernel with `@p0` vector boundary masks (`tl.load(..., mask=mask)`).
- **PTX Assembly Viewer**: Highlights the exact `setp.lt.u32 %p0, %r1, %r2` instruction in the compiled binary that safeguards against GPU memory faults.

### Stage 04: Nsight Profiler & Silicon Memory Waterfall
- **SiliconMemoryWaterfall**: Cascading live memory flow diagram tracing transfer latencies and bandwidth across HBM3e, L2, Shared Memory, and Tensor Registers.
- **NsightTelemetryHud**: Dual-gauge and sparkline displays for 418.5 TFLOPS FP16 throughput, 2.84 TB/s effective memory bandwidth, and 98.2% SM execution occupancy.

## 4. Engineering Trade-Offs & Architectural Decisions

Every design choice carries intentional trade-offs tailored to Nebius and NVIDIA hackathon evaluation:

1. **Tabbed Stage Decoupling vs. Infinite Unified Canvas**:
   - *Choice*: 4-stage curated workbench tabs.
   - *What We Gain*: Zero visual congestion, crisp cognitive focus, fast render loops, and guaranteed responsiveness on standard laptop displays.
   - *What We Give Up*: Simultaneous bird's-eye view of all 8 instruments on a single screen. (Mitigated by top-level telemetry badges and summary status in the header).

2. **SVG-Based Microarchitecture Simulation vs. WebGL 3D Canvas**:
   - *Choice*: Lightweight SVG + CSS hardware acceleration for 132 SMs and 32-thread warps.
   - *What We Gain*: Zero WebGL initialization overhead, 100% deterministic layout across devices, instant state updates, zero canvas context loss, and full DOM inspectability.
   - *What We Give Up*: Free 3D orbital camera rotations of the physical GPU package.

3. **EventSource SSE vs. Bi-Directional WebSocket**:
   - *Choice*: Server-Sent Events (`EventSource`) for live proving pipeline feeds.
   - *What We Gain*: Automatic reconnection, HTTP/2 multiplexing, native browser streaming support, and trivial backend implementation.
   - *What We Give Up*: Bi-directional client message frames over the same socket (client actions use clean REST calls instead).
