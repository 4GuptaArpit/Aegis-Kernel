# Aegis-Kernel UI-UX Architecture & Design System Specification

## 1. Assumptions

1. **Host Environment**: Modern Chromium/Firefox browser with WebGL/GPU acceleration support, 1080p to 4K resolution displays, running React 18+ and Tailwind CSS.
2. **Backend Telemetry & SSE**: The frontend communicates with `http://localhost:8000/api/v1/execute/{fixture}` via Server-Sent Events (SSE). When the backend is offline, unreachable, or in development mode, the UI falls back defensively to deterministic synthetic stream fixtures rather than failing silently or freezing.
3. **Hardware Scope**: While primary visualization focuses on NVIDIA Hopper GH100 (132 SMs, SM_90a), the interface seamlessly switches topologies and metrics for Ada Lovelace L40S (142 SMs, SM_89) and Blackwell B200 (160 SMs, SM_100).
4. **Target Audience**: High-performance computing engineers, kernel developers, and AI researchers from NVIDIA, Nebius, and leading labs who evaluate architectural fidelity, warp divergence, and latency improvements.

## 3. Dialectical Architectural Analysis

### Thesis: The Dense Monolithic HUD
- **Premise**: Supercomputer tools (e.g., Bloomberg terminals, CAD systems, hardware debuggers) provide maximum utility by exposing all instruments simultaneously on a single canvas.
- **Flaws in Practice**: Visual overload, cramped 600px vertical scrolling sections, overlapping data columns, and visual fatigue during live hackathon demos.

### Antithesis: The Minimalist Linear Wizard
- **Premise**: Break the application into sequential modal dialogs or isolated wizard steps, displaying only one single metric or chart at a time.
- **Flaws in Practice**: Destroys the feeling of an authoritative supercomputing workbench; prevents cross-instrument correlation (e.g., inspecting Warp 0 thread masking while viewing the 132-SM Die and L2 crossbar).

### Synthesis: The 4-Stage Coordinated Spatial Workbench
- **Resolution**: A multi-stage spatial command architecture where each stage groups 2 to 3 contextually coupled instruments with ample breathing room (1580px container, 24px gap). Users maintain complete situational awareness through the unified `ExecutiveCommandBar` (persistent hardware switcher, sequence length scrubber, and live pipeline status) while navigating dedicated stages:
  1. **Stage 01: Red vs Blue Collider & Delta**: Nemotron-3 Red Fuzzer vs Nemotron Blue Healer, Delta Speedup, and Terminal Feed.
  2. **Stage 02: 132-SM Die & 32-Warp Matrix**: Physical GH100 silicon core grid mapped directly to SIMT 32-thread micro-lanes and Nsight HUD.
  3. **Stage 03: AST Diff & PTX Disassembly**: Side-by-side CUDA C++ vs Hardened Triton Python with `@p0` predication syntax.
  4. **Stage 04: Nsight Profiler & Memory Waterfall**: 4-Tier memory hierarchy dataflow and hardware telemetry HUD.

## 5. Hardware-Authentic Component Specifications

### 5.1 Executive Command Cockpit (`ExecutiveCommandBar.jsx`)
- **Hardware Architecture Selector**: Instant toggle between Hopper H100 (80GB, SM_90a, 3.35 TB/s), Ada L40S (48GB, SM_89, 864 GB/s), and Blackwell B200 (192GB, SM_100, 8.0 TB/s).
- **Dynamic Sequence Scrubber**: Interactive range slider adjusting sequence length from 128 to 4096 tokens. Live calculation of ragged warp boundaries (`seqLen % 32`) with visual warnings when tail threads require predication.
- **Proving Loop Trigger**: High-voltage execute button with stage tracking indicators (`01 Tavily Recon` -> `02 Red Fuzzer` -> `03 Sandbox Crash` -> `04 Nemotron Blue` -> `05 Dual Invariant`).

### 5.2 132-SM Silicon Die Topology (`HopperDieTopology.jsx`)
- **Full GH100 Floorplan**: Accurate rendering of all 132 Streaming Multiprocessors arranged across 8 Graphics Processing Clusters (GPCs).
- **Memory Subsystem Interconnect**: Quad HBM3e controllers linked via a 50MB High-Speed L2 Cache Crossbar (3.35 TB/s highway).
- **Dynamic State Reflection**:
  - *Normal/Idle*: Subdued emerald glow with core interconnect heartbeats.
  - *Fuzzer Attack*: Faulting SM 14 flashes plasma coral with `CRITICAL: SM 14 MMU PAGE TRAP`.
  - *Blue Healed*: Coalesced emerald wave across all 132 SMs with zero-penalty predication.

### 5.3 SIMT 32-Thread Warp Matrix (`WarpVisualizer.jsx`)
- **32 Physical Lane Grid**: Visual representation of thread lanes T0 through T31.
- **Mode Comparison**: Interactive toggle between `Unprotected CUDA (Crash)` and `Aegis Hardened Triton (Immune)`.
- **Register & Memory Inspector**: Real-time breakdown of the selected lane:
  - Hardware lane index and hexadecimal memory address (`0x7F4E82...`).
  - Physical `@p0` predicate register status (`@p0 = 1` execute vs `@p0 = 0` masked).
  - PTX assembly instruction comparison (`ld.global.v2.f16` vs `@p0 ld.global.nc.v2.f16`).

### 5.4 4-Tier Silicon Memory Waterfall (`SiliconMemoryWaterfall.jsx`)
- **Tier 1 (Global HBM3e VRAM)**: 80 GB, 3.35 TB/s, ~250 cycles latency. Visualizes reduction from 3x unfused round-trips to 1x streamed IO.
- **Tier 2 (L2 Crossbar Cache)**: 50 MB, 12.0 TB/s, ~35 cycles latency. Displays 94.2% hit rate via 128-bit coalesced tiling.
- **Tier 3 (SM Shared Memory / SRAM)**: 228 KB per SM (30 MB chip-wide), 33.0 TB/s, ~18 cycles latency. Highlights activation fusion in registers without DRAM traffic.
- **Tier 4 (Tensor Core ALU & Register File)**: 64K registers per SM, 989 TFLOPS peak, 1 cycle latency. Proves 418.5 TFLOPS sustained compute.

### 5.5 Nsight Telemetry & Compute HUD (`NsightTelemetryHud.jsx`)
- **Sampling Frequency**: High-frequency 100KHz hardware metric polling simulation.
- **Telemetry Indicators**: SM Occupancy (100%), Tensor Core Throughput (418.5 TFLOPS), HBM3e Saturation (2.84 TB/s), SRAM Allocation (184 KB / 228 KB), Warp Divergence (0.0%), and PTX Register Pressure (32 Regs/Thread).

## 6. Defensive Engineering & Failure Resilience

1. **Hostile Network Fallback**:
   - The SSE stream listener wraps parser routines in a strict try-catch block.
   - If the backend is disconnected or returns an HTTP error code, `App.jsx` automatically falls back to an internal deterministic state machine, ensuring flawless demo execution without blank screens or console errors.
2. **Audio Context Protection**:
   - Web Audio API calls are wrapped in user-interaction guards. If audio autoplay is blocked by the browser policy, sound effects gracefully mute without throwing uncaught exceptions.
3. **Ragged Bounds Safety**:
   - Sequence length scrubbing enforces clamped ranges (128–4096) with explicit integer parsing. Thread matrix indices never throw out-of-bounds indexing errors regardless of user input.
