## 2. Core Architectural Principles: Solving Spatial Congestion

Previous hackathon submissions fell into two traps:
1. **Vertical Monolith Congestion:** Stacking 8 dense visualizers vertically, forcing endless 600px scrolling and overlapping UI elements.
2. **Generic Card Dashboards:** Wrapping complex hardware telemetry into uniform rounded boxes with generic charts, lacking hardware authenticity.

Aegis-Kernel solves this through a **4-Stage Spatial Stage Decoupling Engine**:

| Stage ID | Domain Name | Core Visualizers | Breathing Room & Ergonomic Focus |
|:---|:---|:---|:---|
| **Stage 01** | **Red vs Blue Collider & Empirical Delta** | `RedBlueArena`, `MicDropDelta`, `VerificationImpact`, `TerminalWindow` | Dual combat arena with central reactor core, clear 50/50 comparison split, and live terminal drawer. |
| **Stage 02** | **Silicon Die & 32-Warp Matrix** | `HopperDieTopology` (132 SMs), `WarpVisualizer` (32 Lanes), `NsightTelemetryHud` | Silicon-level inspection. Left: 132-SM wafer die with animated L2 crossbar. Right: 32-lane SIMT warp showing `@p0` predication. |
| **Stage 03** | **AST Diff & PTX Disassembly** | `CodeDiffInspector` (Dual Mode: C++/Triton & PTX ISA), `TerminalWindow` | Side-by-side split code terminal with line annotations for out-of-bounds dereferences and hardware predication masks. |
| **Stage 04** | **Nsight Profiler & Memory Waterfall** | `NsightTelemetryHud` (6-tile 100KHz HUD), `SiliconMemoryWaterfall` (4-tier dataflow), `VerificationImpact` | Complete hardware dataflow from 80GB HBM3e down to 1-cycle Tensor Core ALUs, highlighting SRAM fusion benefits. |

### 3.2 Hardware Components Detailed Breakdown

#### A. 132-SM Hopper GH100 Physical Die (`HopperDieTopology.jsx`)
- **Die Topology:** Visualizes all 132 physical Streaming Multiprocessors across 8 Graphics Processing Clusters (GPCs).
- **L2 Cache Highway:** An animated 50 MB L2 Cache crossbar streaming data at 3.35 TB/s between 4 HBM3e memory stacks (834 GB/s per bank).
- **Interactive Trap Pinpointing:** When the Red Fuzzer injects an unaligned sequence length, core **SM 14** flashes in pulsating `#FF0055` coral with an MMU page fault indicator, demonstrating the exact physical core suffering a bus exception.
- **Triton Shield State:** Upon patch synthesis, all 132 SMs light up in unified `#00FF88` laser emerald, representing 100% occupancy with zero-penalty predication.

#### B. SIMT Warp 0 Execution Matrix (`WarpVisualizer.jsx`)
- **32-Thread Lane Inspection:** Renders all 32 hardware threads (`T0` through `T31`) of Warp 0.
- **Dynamic Ragged Boundary:** Linked to the sequence length scrubber (`seqLen`). If `seqLen = 1023`, the boundary is at thread 17 (`1023 % 32 = 17`).
- **Hardware Predication Toggle:**
  - *Unprotected CUDA Mode:* Threads 17–31 trigger `SIGSEGV 139` with out-of-bounds virtual memory dereferences.
  - *Aegis Hardened Triton Mode:* Threads 17–31 activate `@p0 = 0`, hardware-suppressing global memory transactions and substituting zero-registers in 0 clock cycles.
- **Live Disassembly Box:** Shows real-time PTX instructions (`@p0 ld.global.nc.v2.f16`) and virtual memory addresses per thread lane.

#### C. Silicon Memory Hierarchy Waterfall (`SiliconMemoryWaterfall.jsx`)
Visualizes the 4-tier dataflow transit times:
1. **Tier 1: Global VRAM (HBM3e)** — 80 GB, 3.35 TB/s, ~250 cycles latency. Shows how Triton reduces bus traffic by -42%.
2. **Tier 2: L2 Crossbar Cache** — 50 MB, 12.0 TB/s, ~35 cycles latency. 94.2% hit rate via 128-bit coalescing.
3. **Tier 3: SM Shared Memory / SRAM (TMA)** — 228 KB per SM, 33.0 TB/s, ~18 cycles latency. Zero DRAM round-trip activation fusion.
4. **Tier 4: Tensor Core ALUs** — 64K registers per SM, 989 TFLOPS peak, 1 cycle latency. 418.5 TFLOPS sustained execution.

#### D. Nsight Compute Telemetry HUD (`NsightTelemetryHud.jsx`)
Real-time 100 kHz sampling HUD delivering 6 critical hardware KPIs:
- **SM Occupancy:** `100.0%` (32 active warps per SM)
- **Tensor Core Throughput:** `418.5 TFLOPS` (Hopper 4th Gen FP16/BF16)
- **HBM3e Bandwidth:** `2.84 TB/s` (84.8% bus saturation)
- **SRAM Allocation:** `184 KB / 228 KB` (Zero bank conflicts)
- **Warp Divergence:** `0.0%` (Hardware masked branch suppression)
- **PTX Register Pressure:** `32 Regs/Thread` (0 local memory spills)

## 5. Adversarial Hardening & Edge-Case Resilience

To guarantee the design survives the harshest expert scrutiny, every component was stress-tested against microarchitectural and UI edge cases:

| Failure Mode / Edge Case | Adversarial Attack | Aegis-Kernel Defensive Architecture |
|:---|:---|:---|
| **Zero / Exact Warp Boundary** | `seq_len = 1024` (`1024 % 32 == 0`) — does the visualizer break or show false OOB? | The scrubber and visualizer detect `tailThreads === 0`, shifting to a clean full-warp badge: `CLEAN WARP MULTIPLE: 32/32 LANES COALESCED`, disabling false fault warnings. |
| **Extreme Ragged Tail** | `seq_len = 1` or `seq_len = 33` (`tailThreads === 1`) — single thread active, 31 masked. | SIMT Warp matrix highlights `T0` active and isolates `T1-T31` under predicate mask `@p0=0`, proving bank conflict avoidance even at 97% tail raggedness. |
| **Rapid Hardware Switching During Run** | User clicks Blackwell B200 while SSE proving stream is running on Hopper H100. | All selectors are disabled and locked (`disabled={isRunning}`) with visual lock icons and state isolation, preventing race conditions or socket tears. |
| **SSE Connection Interruption** | Network drop or backend failure during live SSE stream. | `eventSource.onerror` cleanly triggers fallback state, releases UI lock, logs actionable error diagnostic in Terminal, and preserves partial telemetry. |
| **High-DPI / Small Screen Viewport** | 1366x768 laptop vs 4K workstation monitor. | The spatial tabs enforce a fixed max-width container (`1580px`) with responsive CSS grid (`@media (max-width: 1200px)` stacking to single-column) ensuring zero horizontal clipping. |
