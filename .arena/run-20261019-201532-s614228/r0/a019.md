## 1. Executive Summary & Design Philosophy

The **Aegis-Kernel UI-UX Architecture** transforms an autonomous GPU invariant and kernel proving engine into a mission-critical, cyber-physical command bridge. Aegis-Kernel demonstrates a real-time, closed-loop clash between the **Nemotron Red Adversary Fuzzer** (identifying out-of-bounds memory bugs, warp divergence, and race conditions) and the **Nemotron Blue Healer** (synthesizing hardened Triton kernels protected by `@p0` hardware predication).

### The Three Architectural Tenets
1. **Uncompromising Hardware Authenticity**: High-Performance Computing (HPC) software engineers and GPU kernel researchers expect interfaces that respect physical reality. The UI treats the GPU silicon not as an abstract metaphor, but as real physical microarchitecture: 132 Hopper Streaming Multiprocessors (SMs), 32-thread SIMT warp execution matrices, 4-tier memory waterfalls (HBM3e -> L2 Crossbar -> Shared Memory/SRAM -> Tensor Register Files), and nanosecond-level Nsight 100KHz telemetry.
2. **Kinetic Non-Congested Spatial Topology**: Dense engineering tools frequently devolve into cramped, monolithic dashboards where widgets fight for viewport real estate. Aegis-Kernel solves this through an unconstrained **4-Stage Spatial Stage Navigator** and dual-tier spatial hierarchy. Every instrument has breathing room, micro-metric isolation, optical padding (minimum 24px gutters, max-width 1580px bounded center), and contextual focus zones.
3. **Cyber-Physical High-Energy Aesthetic**: Escaping the tired tropes of generic white-label SaaS dashboards, Aegis-Kernel introduces the **Obsidian Void & Supercomputer Reactor System**: deep `#03060D` obsidian background with multi-frequency radial energy nodes, NVIDIA Emerald (`#00FF88`) laser glows for verified formal invariants, Crimson Plasma (`#FF0055`) for hardware fault traps, and Quantum Cyan (`#00F0FF`) for bus telemetry and PTX ISA instructions.

## 2. Technical Assumptions & System Scope

To ensure mathematical precision across all interactive proving grounds, the following architectural assumptions are enforced:
1. **Target Microarchitectures**:
   - **NVIDIA Hopper GH100 SXM5**: 132 SMs, 4 TPCs per GPC, 128 KB SMEM/L1 per SM, 50MB shared L2 cache, 80GB HBM3e delivering 3.35 TB/s bandwidth, SM_90a compute capability.
   - **NVIDIA Blackwell B200**: 160 SMs, 2nd-gen Transformer Engine, 192GB HBM3e delivering 8.0 TB/s bandwidth, SM_100 compute capability.
2. **SIMT Warp Execution Model**:
   - 32 thread lanes per warp (Lane 0 to Lane 31). Dynamic ragged tensor sizes (`seq_len % 32 != 0`) activate inactive thread lane masks visualized via `@p0` hardware predication bitmasks.
3. **Telemetry Streaming Architecture**:
   - Real-time Server-Sent Events (SSE) stream over `http://localhost:8000/api/v1/execute/{fixture}` with 5 execution pipeline stages: `TAVILY_RECON` -> `RED_ATTACK` -> `SANDBOX_FAIL` -> `BLUE_SYNTHESIS` -> `DUAL_VERIFY` -> `COMPLETE`.

### Stage 01: Red vs Blue Collider & Delta
- **Primary Viewport**: `RedBlueArena`
  - Split battleground showcasing **Nemotron Red Fuzzer** vs **Nemotron Blue Healer**.
  - Dynamic radar scanline displaying vulnerability classification (OOB Read, Warp Divergence, Race Condition).
- **Secondary Balanced Grid (2-Column)**:
  - `MicDropDelta`: 2.35x speedup benchmark comparison with bar graphs and GFLOPS/Watt power efficiency gains.
  - `VerificationImpact`: Formal invariant attestation card with one-click Nebius Cloud PR generation.
- **Telemetry Stream**: `TerminalWindow` with color-coded stdout/stderr logs and stack traces.

### Stage 02: 132-SM Die Topology & 32-Warp Matrix
- **Hopper GH100 Full Die Map**:
  - Interactive grid displaying all 132 SMs arranged in 8 Graphics Processing Clusters (GPCs).
  - Hover and click inspection of individual SM state (Idle, Fuzzing, Memory Fault, Healed).
  - Dedicated inspector for SM 14 (primary adversary impact point).
- **32-Thread SIMT Warp Visualizer**:
  - Direct visualization of Warp 0 across all 32 thread lanes (`Lane 00` through `Lane 31`).
  - Clear distinction between active calculation threads and predicated-off tail threads (`@p0 == 0`).
- **Telemetry Strip**: `NsightTelemetryHud` showing live SM occupancy (98.4%) and warp issue rate.

### Stage 03: AST Diff & PTX Disassembly Inspector
- **Side-by-Side Code Diff**:
  - Left pane: Vulnerable raw CUDA C++ kernel highlighting missing boundary guard.
  - Right pane: Hardened Triton Python kernel featuring `@p0` boundary predication and vectorized pointers.
- **PTX Assembly Disassembler**:
  - Live inspection of compiled PTX ISA instructions (`ld.global.nc.v4.u32`, `st.shared.b32`, `@p0 bra $L__tail`).
- **Terminal Execution Feed**: Full stack trace and compiler verification output.

### Stage 04: Nsight Profiler & 4-Tier Memory Waterfall
- **Nsight Telemetry HUD**:
  - High-frequency metrics: 418.5 TFLOPS Tensor throughput, 2.84 TB/s HBM bandwidth utilization, 98.4% compute efficiency.
- **Silicon Memory Hierarchy Waterfall**:
  - Vertical physical flow: **HBM3e (80GB)** -> **L2 Cache (50MB)** -> **Shared Memory/SRAM (228KB/SM)** -> **Tensor Core Register Files**.
  - Bandwidth meters and latency indicators (from 420ns down to 1.8ns).
