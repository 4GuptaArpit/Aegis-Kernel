# Aegis-Kernel UI-UX Architecture & Design System

## Executive Summary
**Aegis-Kernel** is an autonomous GPU invariant and kernel proving workbench engineered for the **Nebius x NVIDIA Global AI Hackathon '26**. The system visualizes the closed-loop battleground between **Nemotron Red Adversary** (an automated fuzzing agent exposing GPU race conditions, out-of-bounds pointer arithmetic, and warp divergence crashes) and **Nemotron Blue Healer** (an autonomous Triton compiler agent synthesizing verified, memory-safe kernels with zero branch penalties).

This document establishes the comprehensive UI/UX architecture, spatial layout engine, hardware-faithful visualization specifications, and design system for Aegis-Kernel. It replaces dense, congested SaaS dashboards with a cyber-physical supercomputer proving ground designed to meet the rigorous aesthetic and technical standards of NVIDIA and Nebius systems engineers.

---

## Assumptions
1. **Target Hardware Targets**: Focuses primarily on NVIDIA Hopper GH100 (SM_90a, TSMC 4N, 132 SMs, 4 HBM3e stacks delivering 3.35 TB/s, 50MB L2 cache, 228KB SRAM/SM) with runtime switching capability to Ada Lovelace L40S (SM_89) and Blackwell B200 (SM_100).
2. **Workload Presets**: Covers critical frontier LLM serving operations: Fused SwiGLU (LLaMA-3/Mistral ragged batching), Vector RMSNorm (Qwen-2.5/DeepSeek unaligned dimensions), and Online Softmax (FlashAttention-v3 logit overflow).
3. **Execution Model**: Real-time server-sent events (SSE) streaming live adversarial fuzzing, sandbox execution, AST translation, PTX generation, and formal invariant attestation.

## 1. System Map & Second/Third-Order Dynamics

The Aegis-Kernel UI-UX is modeled as an interconnected, feedback-driven cyber-physical instrument rather than a static reporting view:

### Dynamic Coupling and Second/Third-Order Effects:
1. **Parameter Adjustment Dynamics**: Scrubbing the **Dynamic Sequence Length Scrubber** (e.g. from 1024 to 1023 tokens) immediately changes the boundary alignment state. When `seqLen % 32 !== 0`, the ribbon signals a ragged boundary warning. Second-order: this alters the tail thread indices in the **32-Warp Execution Matrix** (Lanes 17-31). Third-order: in the **Silicon Die Topology**, SM 14 MMU flags an unaligned transaction page trap on global bus memory, directly highlighting the vulnerability in the adversarial proving loop.
2. **Adversarial Collision to Silicon Feedback**: When the user triggers `RUN PROVING GROUND`, the 5-stage laser pipeline initiates. Stage 03 (`SANDBOX_FAIL`) triggers an alert sound, causing the central reactor core in Stage 01 to pulse crimson, SM 14 in Stage 02 to flash coral (`SIGSEGV 139`), and the Terminal viewport to stream memory panic offsets (`0x7F4E8240`). Stage 04 transitions to Nemotron Blue synthesis, where Triton injects `@p0` predication, instantly stabilizing the die topology to laser emerald and updating the Nsight HUD to 100% occupancy with zero branch penalties.

## 3. Spatial Workbench Navigation & Decongestion Engine

The core breakthrough of Aegis-Kernel's layout is the **4-Stage Spatial Workbench Navigator**. Rather than stacking eight complex diagnostic engines into an unreadable vertical column, users navigate four focused physical stages:

```
+---------------------------------------------------------------------------------------------------------+
| [01 Red vs Blue Collider & Delta]  [02 132-SM Die & 32-Warp]  [03 AST Diff & PTX]  [04 Nsight & Memory] |
+---------------------------------------------------------------------------------------------------------+
```

### Stage Breakdown:
1. **Stage 01: Red vs Blue Collider & Delta**
   - **Primary Visual**: Central particle-accelerator collision core representing Nemotron Red vs Nemotron Blue.
   - **Complementary View**: Empirical Mic-Drop Delta (before/after breakdown) and Verification Impact summary with live execution terminal feed.
   - **Cognitive Goal**: Immediate executive comprehension of the vulnerability exploit, speedup delta (2.35x), and proof.

2. **Stage 02: 132-SM Die & 32-Warp Matrix**
   - **Primary Visual**: Two-column physical architecture layout. Left: Full 132-SM silicon die map of the NVIDIA Hopper GH100 with 8 GPCs, 50MB L2 crossbar, and 4 HBM3e stacks. Right: SIMT Warp 0 Execution Matrix with 32 distinct hardware thread lanes.
   - **Telemetry View**: Real-time Nsight 100KHz SM telemetry HUD at the bottom.
   - **Cognitive Goal**: Deep silicon-level inspection of hardware divergence, MMU page traps, and thread-lane predication.

3. **Stage 03: AST Diff & PTX Disassembly**
   - **Primary Visual**: Side-by-side code diff inspector with synchronized syntax tokenization and line markers.
   - **Dual Inspection Mode**: Toggle between High-Level Source Diff (unmasked CUDA C++ vs safe Triton Python) and Low-Level PTX Disassembly (unpredicated `ld.global` vs zero-cycle `@p0 ld.global.nc`).
   - **Cognitive Goal**: Transparent code-level auditability for compilers and systems researchers.

4. **Stage 04: Nsight Profiler & Memory Waterfall**
   - **Primary Visual**: 100KHz Nsight Compute Telemetry HUD (TFLOPS, Bus Saturation, SRAM allocation, Warp efficiency).
   - **Memory Dataflow**: 4-Tier Silicon Memory Hierarchy Waterfall tracing data round-trips through HBM3e -> L2 Cache -> SM SRAM -> Tensor Core ALUs.
   - **Cognitive Goal**: Microarchitectural performance proof validating that memory-safe kernels achieve 418.5 TFLOPS roofline saturation.

## 4. Hardware Microarchitecture Authenticity

Aegis-Kernel provides hardware-accurate representation of NVIDIA Hopper GH100 microarchitecture:

```
+---------------------------------------------------------------------------------------------------------+
|                                    NVIDIA GH100 SILICON TOPOLOGY                                        |
|  [HBM3e Stack #0]   ┌────────────────────────────────────────────────────────┐   [HBM3e Stack #2]       |
|   819 GB/s          │  GPC 0..7 : 132 Streaming Multiprocessors (SMs)        │    819 GB/s              |
|                     │  [SM 00] [SM 01] ... [SM 14: FAULT/HEALED] ... [SM131] │                          |
|  [HBM3e Stack #1]   ├────────────────────────────────────────────────────────┤   [HBM3e Stack #3]       |
|   819 GB/s          │  50 MB Ultra-Wide High-Speed L2 Crossbar Cache Interc  │    819 GB/s              |
+---------------------------------------------------------------------------------------------------------+
```

### Key Hardware Specifications Visualized:
- **Streaming Multiprocessors**: 132 active SMs across 8 Graphics Processing Clusters (GPCs) on TSMC 4N process. Clicking any SM focuses real-time thread dispatch telemetry.
- **SIMT Warp Execution**: 32 thread lanes per warp. Thread lanes 0-16 represent valid token bounds; thread lanes 17-31 represent the out-of-bounds tail where raw CUDA panics, while Triton applies `@p0` hardware predication to mask loads to 0.0 with zero branch penalty.
- **Hardware Predication**: PTX ISA `@p0` instruction predicate registers are explicitly highlighted in the disassembly viewer and warp matrix, demonstrating how modern NVIDIA hardware eliminates warp divergence branches.
- **4-Tier Silicon Memory Waterfall**:
  1. *Tier 1: Global VRAM (HBM3e)* — 80 GB, 3.35 TB/s peak bandwidth, ~250 cycle latency.
  2. *Tier 2: L2 Crossbar Cache* — 50 MB, 12.0 TB/s crossbar bandwidth, ~35 cycle latency.
  3. *Tier 3: SM Shared Memory / SRAM (TMA)* — 228 KB per SM (30 MB total die SRAM), 33.0 TB/s aggregate bandwidth, ~18 cycle latency.
  4. *Tier 4: Tensor Core ALUs & Register File* — 64K 32-bit registers, 989 TFLOPS FP16 peak, 1 cycle execution.

## 5. Interactive Proving Ground Specifications

The Executive Command Cockpit provides direct, live control over kernel execution parameters:
- **Dynamic Sequence Length Scrubber**: Range from 128 to 2048 tokens. Immediate interactive feedback indicates whether dimensions are warp-aligned (`seqLen % 32 === 0`) or ragged (`seqLen % 32 !== 0`).
- **Hardware Target Switcher**: Select between NVIDIA Hopper H100 SXM5 (80GB, SM_90a), Ada Lovelace L40S (48GB, SM_89), and Blackwell B200 (192GB, SM_100).
- **Workload Presets**: One-click switching between Fused SwiGLU, Vector RMSNorm, and Online Softmax workloads.
- **Live Proving Execution**: Streams live Server-Sent Events through the 5-stage pipeline with responsive audio cues and animated HUD telemetry.
- **Attestation & Pull Request Modal**: Interactive modal delivering cryptographic verification hashes and instant export of production-ready GitHub PR descriptions.

- `ExecutiveCommandBar.jsx`: Hardware selector, sequence length scrubber, pipeline stepper, proving trigger.

- `HopperDieTopology.jsx`: 132-SM die layout with HBM3e banks and L2 cache crossbar.

- `NsightTelemetryHud.jsx`: 100KHz hardware telemetry HUD with occupancy and compute saturation meters.
- `SiliconMemoryWaterfall.jsx`: 4-tier dataflow hierarchy comparing PyTorch bus round-trips to Triton SRAM fusion.
- `MicDropDelta.jsx`: Empirical proof breakdown highlighting 2.35x speedup and fault resolution.
- `VerificationImpact.jsx`: Verification impact metrics and hardware-reactive roofline model.
- `TerminalWindow.jsx`: Filterable live sandbox telemetry terminal.
- `AttestationModal.jsx`: Cryptographic audit certificate and one-click GitHub PR export.

This architecture delivers a complete, production-grade interface that eliminates visual congestion while maximizing hardware authenticity and aesthetic impact.
