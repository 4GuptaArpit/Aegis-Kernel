## 1. Executive Summary & Problem Diagnosis

### 1.1 The Challenge
Modern GPU kernel development and safety auditing suffer from a severe tooling gap: developers either view raw, detached ASCII terminal dumps from `cuda-memcheck` / Nsight CLI, or generic web dashboards that treat GPU cores as generic CPU metrics. In autonomous fuzzing—where **Nemotron Red Adversary** constructs boundary-breaking tensor shapes (e.g., $N=1023$, unaligned 128-bit loads) and **Nemotron Blue Triton Healer** synthesizes hardware-predicated kernels—judges and HPC architects demand an interface that reveals silicon realities in real time without cognitive congestion.

### 1.2 Baseline Shortfalls & The "GA-GA" Remedy
The previous design baseline introduced a 4-tab spatial workbench but remained fragmented:
1. **Disconnected Context**: The user had to flip between tabs to correlate an SM memory trap in the Die Topology with the faulty instruction in PTX disassembly and the resulting bandwidth degradation in Nsight telemetry.
2. **Static Viewports**: Visualizations lacked dynamic interactivity (e.g., inspecting individual warp thread lanes under ragged tensor lengths, simulating clock cycle latencies, or tracking exact `@p0` predicate bitmasks across warps).
3. **Congestion vs. Information Density Trade-off**: The layout oscillated between cramped 600px vertical columns and overly empty tab spaces.

**Aegis-Kernel UI-UX 2.0** solves this with an **Elite HPC Supercomputer Cockpit** architecture:
- **Obsidian-Emerald-Plasma Cyber-Physical Palette**: True deep-space contrast (`#03060D` obsidian void, `#00FF88` NVIDIA laser emerald, `#FF0055` crimson plasma, `#00F0FF` electric cryogenic cyan, and `#FFB800` warning amber).
- **Hierarchical Spatial Staging with Fluid Micro-Pillars**: Unified Executive Command Cockpit coupled with an adaptive 4-stage workbench and a persistent Silicon Status ribbon.
- **Hardware-Accurate Microarchitecture**: Exact TSMC 4N Hopper GH100 silicon topology (132 Streaming Multiprocessors across 8 GPCs, 6 HBM3e stacks delivering 3.35 TB/s, 50MB unified L2 cache, 32-thread SIMT warp execution matrix with real-time `@p0` hardware predicate bitmask tracking).

## 4. Detailed Component Specifications

### 4.1 Executive Command Cockpit (`ExecutiveCommandBar.jsx`)
- **Primary Control Strip**:
  - **Workload Selector**: Tabbed selection for `swiglu` (Fused SwiGLU, LLaMA-3/Mistral), `rmsnorm` (Vector RMSNorm, Qwen-2.5/DeepSeek), and `softmax` (Online Softmax, FlashAttention-v3). Displays real-time expected crash type (`SIGSEGV 139`, `Silent SDC`, `NaN Overflow`) and verified speedup target.
  - **Hardware Architecture Switcher**: Dropdown supporting Hopper H100 SXM5 (SM_90a, 80GB, 3.35 TB/s), Ada Lovelace L40S (SM_89, 48GB, 864 GB/s), and Blackwell B200 (SM_100, 192GB, 8.0 TB/s).
  - **Dynamic Sequence Scrubber**: Interactive slider ($N \in [512, 4096]$ tokens). When $N \not\equiv 0 \pmod{32}$, flags immediate visual **RAGGED TENSOR ALERT** indicating that warp tail threads require `@p0` predication to prevent OOB memory violations.
  - **One-Click Autonomous Proving Trigger**: Pulsing high-energy emerald CTA with micro-interaction state machine (`IDLE` $\rightarrow$ `TAVILY` $\rightarrow$ `RED_ATTACK` $\rightarrow$ `SANDBOX_FAIL` $\rightarrow$ `BLUE_SYNTHESIS` $\rightarrow$ `COMPLETE`).

### 4.2 Stage 01: Red vs Blue Collider & Mic-Drop Delta
- **Autonomous Dual-Reactor Arena**:
  - **Nemotron Red Adversary (Crimson Void `#FF0055`)**: Displays the generated hostile tensor tensor shapes ($N=1023$, unaligned float16 pointers), memory boundary access vectors, and sandbox execution crash output (`CUDA_ERROR_ILLEGAL_ADDRESS: SM 14 MMU Page Fault`).
  - **Nemotron Blue Healer (NVIDIA Emerald `#00FF88`)**: Displays the synthesized Triton kernel, automatic tile boundary clamping (`tl.cdiv`), and masked vector load primitives (`tl.load(ptr, mask=mask, other=0.0)`).
- **Mic-Drop Speedup & Delta Visualizer**:
  - Large-format metrics displaying unoptimized baseline execution time ($142.8\,\mu\text{s}$) vs healed Triton execution time ($60.7\,\mu\text{s}$), yielding a verified **2.35x speedup**.
  - Arithmetic intensity comparison showing jump from $14.2\,\text{FLOP/byte}$ to $34.8\,\text{FLOP/byte}$.
- **Attestation & Cryptographic Invariant Card**:
  - Displays formal SHA-256 silicon attestation hash (`0x7f56b9fe02089399`) verifying zero out-of-bounds reads across $10^7$ synthetic fuzz iterations.

### 4.3 Stage 02: 132-SM Hopper Die & 32-Warp Matrix
- **GH100 Silicon Floorplan**:
  - Complete 132 Streaming Multiprocessor matrix laid out across 8 Graphics Processing Clusters (GPCs).
  - High-bandwidth memory flanking channels visualizing 6 HBM3e stacks (6144-bit bus).
  - Interactive SM selection: Clicking any SM core (default: SM 14) reveals its real-time warp scheduler status, register allocation ($65,536 \times 32$-bit registers per SM), and shared memory partition ($228\,\text{KB}$ per SM).
  - Visual fault beacon: During `SANDBOX_FAIL`, SM 14 pulses with high-frequency crimson strobe and localized particle disruption, transitioning to calm laser emerald upon `BLUE_SYNTHESIS_COMPLETE`.
- **SIMT 32-Thread Warp Matrix**:
  - 32 discrete thread lanes (Lane 0 to Lane 31) visualizing lockstep execution of Warp 0.
  - Individual thread lane card inspector: Clicking a thread lane displays its physical memory target address, vector payload, predicate register value (`@p0 = 1` vs `@p0 = 0`), and hardware register state.
  - Tail boundary visualizer: Clearly delineates valid threads (0–16) from ragged tail threads (17–31), demonstrating how unpredicated code triggers bus errors while predicated Triton code executes zero-overhead suppression.

### 4.4 Stage 03: AST Diff & PTX Disassembly
- **Side-by-Side Dual Editor**:
  - **Left Pane (Vulnerable CUDA C++)**: Highlights unmasked raw pointer indexing (`float2 val = *reinterpret_cast<float2*>(in + idx);`) with red diff gutters and memory hazard tooltips.
  - **Right Pane (Hardened Triton Python)**: Highlights vector masking constructs (`mask = offs < seq_len; tl.load(ptrs, mask=mask, other=0.0)`) with emerald diff gutters.
- **PTX ISA Assembly Inspector**:
  - Displays compiled SM_90a assembly code with syntax-highlighted hardware predication:
    ```ptx
    setp.lt.u32    %p0, %r4, %r8;         // Predicate evaluation
    @%p0 ld.global.nc.v2.f16 {%r1,%r2}, [%rd3]; // Hardware-predicated load
    @!%p0 mov.b32   {%r1,%r2}, 0x00000000; // Zero register invariant
    ```

### 4.5 Stage 04: Nsight Profiler & 4-Tier Memory Waterfall
- **100KHz Hardware Telemetry HUD**:
  - Real-time gauge bars and sparklines for Tensor Core throughput ($418.5\,\text{TFLOPS}$ sustained, $42.3\%$ theoretical peak for FP16/BF16 dense).
  - DRAM bandwidth utilization ($2.84\,\text{TB/s}$, $84.8\%$ of HBM3e peak).
  - SM warp occupancy ($91.7\%$) and warp divergence counter ($0.0\%$ under predication).
- **Silicon Memory Hierarchy Waterfall**:
  - Multi-tier visual data pipeline tracing transaction flow from **HBM3e** ($3.35\,\text{TB/s}$, 450 cycles latency) $\rightarrow$ **50MB L2 Cache** ($12.0\,\text{TB/s}$, 180 cycles) $\rightarrow$ **Shared Memory / L1 SRAM** ($33.0\,\text{TB/s}$, 32 cycles) $\rightarrow$ **Tensor Cores / Register File** ($1.2\,\text{PFLOPS}$, 4 cycles).
  - Coalescing efficiency gauge displaying $100\%$ 128-byte transaction packing with zero wasted bus cycles.

### 5.2 Layout & Spacing Rules
1. **Container Consistency**: Outer container capped at `1580px` with uniform `24px` horizontal padding.
2. **Breathing Room**: Component cards enforce a minimum `20px` internal padding and `16px` grid gap, preventing visual crowding.
