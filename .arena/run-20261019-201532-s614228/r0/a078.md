# Aegis-Kernel UI-UX Architecture & Design System

## Executive Summary & Design Thesis

Aegis-Kernel is an autonomous GPU invariant and kernel proving workbench engineered for the Nebius x NVIDIA Global AI Hackathon '26. The platform proves memory safety and performance equivalence between unhardened baseline kernels (vLLM / FlashAttention / PyTorch C++) and Nemotron Blue-synthesized Triton kernels on NVIDIA Hopper GH100 (SM_90a) and Blackwell B200 (SM_100) silicon.

To address previous design shortcomings—namely visual congestion, generic cards, and surface-level aesthetic swaps—Aegis-Kernel implements a **Hierarchical 4-Tier Spatial Cockpit** built on a **Cyber-Physical Quantum Supercomputer System**. This architecture provides uncompromising breathing room (maximum 2-3 major analytical instruments per viewport), hardware-authentic spatial topologies (132-SM die floorplan, SIMT 32-thread lockstep register matrix, 4-tier memory waterfall), and zero-latency interactive proving ground controls.

---

## Assumptions

1. **Target Hardware Fidelity**: The primary target is NVIDIA Hopper GH100 SXM5 (132 SMs across 8 GPCs, 6 HBM3e stacks, TSMC 4N process node) with fallback telemetry parameters for Blackwell B200 (160 SMs, 8.0 TB/s) and Ada Lovelace L40S (142 SMs, 864 GB/s).
2. **Execution Protocol**: Live proving loops connect over Server-Sent Events (`/api/v1/execute/{fixture}`) streaming state transitions: `INIT` → `TAVILY_RECON` → `RED_ATTACK_SYNTHESIS` → `SANDBOX_RED_EXECUTE` (SIGSEGV/SDC trigger) → `BLUE_SYNTHESIS` → `DUAL_VERIFY` → `COMPLETE`.
3. **Display Constraints**: Optimized for high-density developer displays (1440p / 4K / ultrawide 21:9) down to standard 1080p laptop viewports via dynamic responsive grid collapsing.

### Spatial Stage Specifications

#### Stage 01: Red vs Blue Collider & Mic-Drop Delta
- **Primary Focus**: The battle between Nemotron-3 Ultra (Crimson Adversary Fuzzer) and Nemotron-70B (Emerald Triton Healer).
- **Layout**: Two-column layout pairing the real-time collision arena with the quantitative performance delta (2.35x speedup, 0.00% SDC, 0 local memory spills).
- **Decongestion Metric**: Terminal log stream anchored at the base with auto-scroll and status filtering.

#### Stage 02: 132-SM Die Topology & 32-Warp Matrix
- **Primary Focus**: Authentic low-level hardware visualization.
- **Components**:
  1. *Hopper GH100 Die Grid*: 132 individually interactive Streaming Multiprocessor tiles grouped into 8 GPCs. Fault injection dynamically flashes SM 14 in crimson upon out-of-bounds memory trap.
  2. *SIMT 32-Thread Warp Matrix*: Detailed view of Warp 0. Thread lanes 0–16 render in emerald (`@p0 = 1`, active load), while ragged tail lanes 17–31 show hardware predication (`@p0 = 0`, suppressed register write, zero-cycle penalty).
- **Decongestion Metric**: Fixed-aspect grid layout with side-by-side core vs thread drill-down.

#### Stage 03: AST Diff & PTX Disassembly
- **Primary Focus**: Compiler-level verification.
- **Features**: Side-by-side syntax-highlighted diff contrasting raw CUDA C++ pointer arithmetic (`in_ptr[token_idx * stride]`) with hardened Triton Python (`tl.load(..., mask=mask_m, other=0.0)`).
- **PTX Inspection Mode**: Toggle into Hopper PTX assembly to verify instruction-level `@p0 ld.global.nc.v2.f16` predication.

#### Stage 04: Nsight Profiler & Silicon Memory Waterfall
- **Primary Focus**: Deep memory hierarchy and hardware roofline saturation.
- **Dataflow Waterfall**:
  - *Tier 1 (HBM3e)*: 80 GB at 3.35 TB/s (demonstrating -42% bus traffic reduction).
  - *Tier 2 (L2 Crossbar)*: 50 MB at 12.0 TB/s (demonstrating 94.2% cache hit rate).
  - *Tier 3 (SM SRAM / TMA)*: 228 KB/SM at 33.0 TB/s (demonstrating zero HBM round-trip fusion).
  - *Tier 4 (Tensor Core ALUs)*: 418.5 TFLOPS sustained compute (roofline saturation).

## 3. Interactive Proving Controls & State Orchestration

The Executive Command Bar serves as the zero-latency control center:

1. **Hardware Target Switcher**: Real-time hot-swap between Hopper H100 (SM_90a), Ada Lovelace L40S (SM_89), and Blackwell B200 (SM_100), updating bandwidth, core counts, and roofline targets across all views.
2. **Workload Fixture Preset Selector**:
   - `swiglu`: Fused SwiGLU (LLaMA-3 / Mistral) with ragged token boundary fault (SIGSEGV 139).
   - `rmsnorm`: Vector RMSNorm (Qwen-2.5 / DeepSeek) with non-128-bit alignment SDC fault.
   - `softmax`: Online Softmax (FlashAttention-v3) with numerical overflow NaN fault.
3. **Dynamic Sequence Length Scrubber**: Real-time slider (128 to 4096 tokens). Non-multiples of 32 dynamically flag ragged warp boundary alerts (`tailThreads = seqLen % 32`).
4. **Autonomous Execution Trigger**: Initiates dual SSE connection with synthetic fallback, driving multi-channel audio feedback (tactile clicks, alert sirens, laser success chords).

## 4. Hostile Stress-Testing & Hardening Scenarios

Following the *Build, then break* protocol, the UI-UX architecture was subjected to 5 hostile operational scenarios:

### Scenario 1: Extreme Ultrawide & High-DPI Displays (3840×1600 / 4K)
- **Hostile Vector**: Massive horizontal stretching causing telemetry metrics and die grids to scatter across excessive whitespace.
- **Failure Mode**: Loss of visual coherence and eye strain tracking from command bar to stage content.
- **Architectural Patch**: Enforced an inner maximum viewport width of `1580px` (`.aegis-workbench-container`) centered with balanced margin gutters and backdrop energy dissipation.

### Scenario 2: Network Drop / SSE Stream Disconnection During Live Fuzzing
- **Hostile Vector**: The SSE connection drops while at stage `SANDBOX_RED_EXECUTE`.
- **Failure Mode**: The UI hangs indefinitely in a frozen error state with active spinners.
- **Architectural Patch**: Added automatic SSE error recovery that transitions gracefully into an offline interactive simulation mode, preserving last-received telemetry and logging a clear diagnostic message.

### Scenario 3: High-Frequency Sequence Scrubber Spam (100 updates/sec)
- **Hostile Vector**: Rapid dragging of the sequence length scrubber causing hundreds of re-renders and log spam.
- **Failure Mode**: Main thread stutter, audio clipping, and unreadable terminal scrollback.
- **Architectural Patch**: Debounced log emission to the terminal, throttled sound triggers, and used localized CSS transforms for warp matrix lane transitions to keep rendering on the GPU composite thread.

### Scenario 4: Compact Laptop Viewport (1366×768 / 1280×800)
- **Hostile Vector**: Restricted vertical height causing the 4-stage workbench to overflow and clip vital attestation controls.
- **Failure Mode**: User must vertically scroll past the header to see stage navigation tabs.
- **Architectural Patch**: Applied compact utility classes (`max-h-[calc(100vh-140px)]`), made the Executive Command Bar collapsible into an ultra-dense single strip, and enabled independent container-level scrollbars for the code diff and terminal.

### Scenario 5: Color-Blindness & High-Contrast Luminance Check
- **Hostile Vector**: Pure reliance on Red (`#FF0055`) vs Green (`#00FF88`) hue differentiation.
- **Failure Mode**: Protanopia/Deuteranopia users cannot distinguish between adversary attack states and healed invariant states.
- **Architectural Patch**: Reinforced every color-coded element with dual semantic indicators: explicit iconography (`AlertTriangle` vs `ShieldCheck`), textual status tags (`💥 OOB FAULT` vs `🛡️ PREDICATED @p0`), and distinct pulse frequencies (rapid 0.8s flash for faults, stable 2.0s glow for verified invariants).

## 5. Implementation Artifacts & Code Delivery

### Production Integration in `frontend/src/App.jsx`
The refined stage controller coordinates state cleanly across the 4 stages with zero dependency overhead:

```jsx
// Excerpt: Stage Navigation & Workbench Decoupling
<div className="workbench-stage-nav-bar font-mono">
  <div className="stage-nav-tabs">
    {[
      { id: 'collider', num: '01', label: 'Red vs Blue Collider & Delta' },
      { id: 'silicon', num: '02', label: '132-SM Die & 32-Warp Matrix' },
      { id: 'code', num: '03', label: 'AST Diff & PTX Disassembly' },
      { id: 'telemetry', num: '04', label: 'Nsight Profiler & Memory Waterfall' }
    ].map(tab => (
      <button
        key={tab.id}
        className={`stage-nav-btn ${activeWorkbenchTab === tab.id ? 'active' : ''}`}
        onClick={() => { sound.playClick(); setActiveWorkbenchTab(tab.id); }}
      >
        <span className="nav-tag-num">{tab.num}</span>
        <span>{tab.label}</span>
      </button>
    ))}
  </div>
  <div className="stage-nav-telemetry">
    <span className="nav-telemetry-badge">
      <span className="pulse-indicator bg-nvidia inline-block mr-1"></span>
      {currentStage === 'IDLE' ? 'PROVING INSTRUMENT ARMED' : `STAGE: ${currentStage}`}
    </span>
  </div>
</div>
```
