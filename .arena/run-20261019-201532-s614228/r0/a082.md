# Aegis-Kernel UI-UX Architecture & Design System Specification

## 1. Assumptions & Constraints Profile

### 1.1 Assumptions
- Target display standard: 1920x1080 (1080p full HD) and 2560x1440 (1440p QHD) enterprise presentation displays for Nebius & NVIDIA hackathon juries.
- Browser runtime: Modern Chromium/Blink and WebKit runtimes (Chrome 120+, Edge 120+, Safari 17+) supporting hardware-accelerated CSS custom properties, backdrop-filter, sub-grid, and Web Audio API.
- Backend link: FastAPI server streaming Server-Sent Events (SSE) from `http://localhost:8000/api/v1/execute/{fixture}?hardware_target={target}` with stages `INIT`, `TAVILY_RECON`, `RED_ATTACK_SYNTHESIS`, `SANDBOX_RED_EXECUTE`, `BLUE_SYNTHESIS`, `DUAL_VERIFY`, and `COMPLETE`.

### 1.2 Hard Constraints
- **Hardware Accuracy**: 132 SMs (GH100 full die), 32 thread lanes per warp with `@p0` hardware predication, 4-tier memory hierarchy (HBM3e 3.35 TB/s -> L2 Cache 50 MB 12 TB/s -> Shared Memory/SRAM 228 KB/SM 33 TB/s -> Tensor Core Registers 32 KB/SM 65 TB/s), and Nsight 100 kHz telemetry.
- **Visual Congestion Threshold**: Maximum 3 primary cognitive surfaces per viewport; strict vertical scroll budget (< 1200px per workbench tab view); min 16px spatial padding and 24px inter-cluster gutters.
- **Theme Palette Constraint**: Pure `#03060D` obsidian substrate; dual laser accents `#00FF88` (NVIDIA Emerald, 520nm wavelength) and `#FF0055` (Nemotron Crimson/Plasma Coral, 650nm wavelength); `#00F0FF` cryogenic telemetry cyan; `#FFB800` warp divergence amber.
- **Code Integrity**: Zero build warnings, pure React 18+ components with functional state and standard CSS variable tokens.

## 2. Architecture Options Matrix

To deliver an elite interface that eliminates congestion while maximizing visual impact ("GA-GA factor") and technical fidelity, we evaluated three structural options:

| Criterion (Weight 1-5) | Option A: Monolithic Infinite Canvas | Option B: 4-Stage Tab Bar (Baseline) | Option C: Spatial Workbench Cockpit (Winner) |
| :--- | :---: | :---: | :---: |
| **Aesthetic Impact (GA-GA)** (5) | 3/5 (Overwhelming, scattered) | 3/5 (Standard tabs, lacks punch) | **5/5** (Cinematic cockpit, glowing reactor) |
| **Zero Congestion & Breathing Room** (5) | 1/5 (Severe spatial collision) | 4/5 (Isolated tabs, but disjointed) | **5/5** (Focused viewports, balanced density) |
| **Hardware Authenticity** (4) | 3/5 (Partial views cut off) | 4/5 (Static representations) | **5/5** (Active warp predication + SM telemetry) |
| **Interactive Proving Ground** (4) | 2/5 (Inputs lost in canvas) | 3/5 (Standard slider & buttons) | **5/5** (Live scrubber, preset warp, audio HUD) |
| **Production Feasibility** (3) | 2/5 (Heavy pan-zoom overhead) | 5/5 (Straightforward React state) | **5/5** (Zero-warning Vite/Tailwind architecture) |
| **Weighted Total (/105)** | **49 / 105** | **78 / 105** | **104 / 105** |

### Selected Architecture: Option C (Spatial Workbench Cockpit)
Option C elevates the baseline's stage partitioning into an integrated Supercomputer Proving Cockpit. It combines:
1. **Executive Telemetry HUD Header**: Live hardware target selector (`GH100 SXM5` vs `B200 NVL72`), interactive token sequence scrubber (`64` to `8192` tokens with power-of-two snaps), workload fixtures (`swiglu`, `flash_attention_v3`, `layer_norm`, `cross_entropy`), and an SSE collider ignition button.
2. **Dynamic 4-Stage Spatial Perspective**:
   - `01 RED VS BLUE COLLIDER`: Particle collision arena with real-time token throughput deltas, speedup gauge (2.35x), and live verification impact summary.
   - `02 SILICON TOPOLOGY & WARP MATRIX`: Interactive 132-SM die floorplan with heatmapped OOB memory fault highlights alongside the 32-thread SIMT warp matrix displaying `@p0` predication masks (`0xFFFFFFFF` vs `0x00000000`).
   - `03 AST & PTX DISASSEMBLY INSPECTOR`: Dual-pane diff viewer contrasting naive CUDA memory leaks with hardened Triton Python kernels, paired with side-by-side PTX assembly predication.
   - `04 NSIGHT TELEMETRY & SILICON WATERFALL`: 100 kHz profiling gauges (TFLOPS, Memory Bandwidth, Warp Occupancy, Predication Efficiency) coupled to the 4-tier physical memory waterfall diagram.
3. **Reactive Ambient Audio Engine**: Web Audio API synthesizer generating bespoke 440Hz/880Hz micro-beeps, reactor charging swooshes, and crimson alert strobes for hardware interrupts.

      </span>
    </div>
  );
}

### 3.3 Hardware Die Floorplan & Warp Predication Matrix
- **HopperDieTopology.jsx**: Visualizes 132 SMs arranged into 8 GPCs (Graphics Processing Clusters). SM 14 dynamically flashes crimson (`#FF0055`) with radiation rings during `SANDBOX_RED_EXECUTE` when an out-of-bounds stride violation occurs.
- **WarpVisualizer.jsx**: Renders all 32 SIMT thread lanes for Warp 0. Thread lanes 0 through 30 maintain active `@p0 = 1` status (`#00FF88`), while Lane 31 (tripping `seq_len = 1023` boundary) shows predication mask clamping to `@p0 = 0` (`#00F0FF`), preventing the illegal global memory transaction into unmapped virtual address space.

### 3.4 4-Tier Memory Waterfall (`SiliconMemoryWaterfall.jsx`)
Visualizes dataflow latency and bandwidth across physical Hopper GH100 memory stages:
1. **Tier 1: HBM3e High-Bandwidth Memory** (80 GB, 3.35 TB/s, ~400 cycles latency)
2. **Tier 2: L2 Crossbar Cache** (50 MB, 12.0 TB/s, ~120 cycles latency)
3. **Tier 3: Distributed SRAM / Shared Memory** (228 KB/SM, 33.0 TB/s, ~28 cycles latency)
4. **Tier 4: Tensor Core Register File** (32 KB/SM, 65.0 TB/s, 1 cycle latency)
