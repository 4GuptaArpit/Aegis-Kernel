## 1. Executive Summary & Design Mission

### 1.1 The HPC Engineer's Dilemma
GPU kernel engineers, HPC infrastructure architects, and safety auditors operate in high-stakes environments where a single out-of-bounds memory load or silent data corruption (SDC) in an LLM attention kernel can bring down an entire cluster of multi-million-dollar HGX H100 pods or poison training weights across billions of tokens. Today's tools force engineers to choose between two unacceptable extremes:
1. **Raw, disconnected CLI telemetry**: Terminal dumps from `cuda-memcheck`, `compute-sanitizer`, and NVIDIA Nsight Compute CLI that show raw hex pointers and memory dumps completely isolated from the kernel source code, AST transformations, and warp execution states.
2. **Generic SaaS dashboard templates**: Web dashboards styled like generic marketing analytics, featuring white-to-black palette swaps, generic card containers, lack of hardware context, and severe visual congestion where dense components compete for vertical viewport space.

### 1.2 The Aegis-Kernel Experience: An Authentic Supercomputer Cockpit
**Aegis-Kernel** is the world's first autonomous GPU invariant and kernel proving workbench. It pits **Nemotron Red Adversary** (an intelligent fuzzer that synthesizes pathological tensor dimensions, ragged warp boundaries, and unaligned memory strides) against **Nemotron Blue Healer** (an autonomous Triton compiler agent that synthesizes mathematically proven, `@p0`-predicated, memory-safe kernels).

To make NVIDIA and Nebius judges go **"GA-GA"**, the UI/UX architecture must deliver an authentic, high-energy supercomputer command environment that feels like it belongs inside an NVIDIA supercomputing facility or mission-control operations center—competing with the finest interactive technical interfaces on the web while maintaining strict spatial balance, breathing room, and zero visual congestion.

## 3. Assumptions & Scope Boundaries

To eliminate ambiguity and ensure immediate production feasibility, the design operates under the following validated assumptions:
1. **Target Viewport**: The application is primarily targeted at desktop workstations, laptop displays ($1920 \times 1080$), and ultra-wide lab monitors ($2560 \times 1440$ / $3440 \times 1440$) used by AI engineers and hackathon evaluators. Responsive CSS rules fluidly collapse multi-column layouts into single-column cards on smaller displays.
2. **Audio-Visual Subsystem**: Audio feedback utilizes Web Audio API synthetic beeps and alerts (subtle 800Hz clicks, 220Hz saw alert sweeps, and 520Hz harmonic success chords) with a global mute toggle stored in user preferences.
3. **SSE Connection Fallback**: When running offline or without an active backend server, the client UI gracefully demonstrates pre-recorded golden telemetry runs for all three core workloads (`swiglu`, `rmsnorm`, `softmax`).

## 6. Detailed Component Specifications & User Interactions

### 6.1 Executive Command Cockpit (`ExecutiveCommandBar.jsx`)
*The central control station for the entire proving workbench.*
- **Brand Lockup**: Luminous shield icon with animated pulse ring, `AEGIS // KERNEL` typography, and gold-trimmed hackathon badge `NEBIUS × NVIDIA GLOBAL '26`.
- **Workload Selector**: Fast-switch tabs for three real-world model architectures:
  1. `swiglu`: Fused SwiGLU (LLaMA-3, Mistral) $\rightarrow$ Targets ragged boundary `SIGSEGV 139` crash.
  2. `rmsnorm`: Vector RMSNorm (Qwen-2.5, DeepSeek) $\rightarrow$ Targets unaligned stride Silent Data Corruption (SDC).
  3. `softmax`: Online Softmax (FlashAttention-v3) $\rightarrow$ Targets extreme logit FP16 NaN explosion.
- **Hardware Architecture Switcher**: Live dropdown selecting target GPU microarchitectures:
  - `NVIDIA Hopper H100 SXM5` (80GB HBM3e, SM_90a, 3.35 TB/s, 132 SMs)
  - `NVIDIA Blackwell B200` (192GB HBM3e, SM_100, 8.0 TB/s, 160 SMs)
  - `NVIDIA Ada Lovelace L40S` (48GB GDDR6, SM_89, 864 GB/s, 142 SMs)
- **Dynamic Sequence Length Scrubber**: Real-time slider controlling token sequence length ($N \in [512, 4096]$).
  - When $N \not\equiv 0 \pmod{32}$ (e.g., $N=1023$), the system dynamically triggers a flashing crimson badge: `RAGGED TAIL: 31 TOKENS (% 32 != 0)`.
  - Audio chirp confirms slider adjustments while updating simulated memory addresses across all stages.
- **Autonomous Proving Ground CTA**: High-energy gradient button with animated outer laser glow. Clicking triggers the real-time SSE stream with audible launch sound, locks inputs during active fuzzing, and updates the 5-phase pipeline stepper (`01 TAVILY` $\rightarrow$ `02 RED FUZZER` $\rightarrow$ `03 SANDBOX CRASH` $\rightarrow$ `04 NEMOTRON BLUE` $\rightarrow$ `05 DUAL INVARIANT`).

### 6.2 Stage 01: Red vs Blue Collider & Mic-Drop Delta
*The visual battleground where the bug is synthesized, exploited, and healed.*

  - **Blue Healer Wing (Emerald `#00FF88`)**: Features pulsing shield icon, Triton code patch synthesis progress, and real-time validation of hardware boundary predicate mask `@p0`.
- **Mic-Drop Vulnerability & Hardening Delta (`MicDropDelta.jsx`)**:
  - **Side-by-side comparison**: Juxtaposes the Production PyTorch Baseline (Crashes at ragged sequence #17, `SIGSEGV 139`, $54.2\,\mu\text{s}$) with Aegis Hardened Triton (500/500 shapes passed, `Exit 0`, $23.1\,\mu\text{s}$).
  - **Central Speedup Pill**: Large-format **2.35x SPEEDUP** badge highlighting the double-win: formal mathematical safety plus superior execution latency.
- **Verification Impact & Attestation (`VerificationImpact.jsx`)**:
  - **Donut Gauge**: Radial SVG meter showing 100% invariant reliability ($0.00\,\text{SDC}$ rate across 500 ragged test tensors).
  - **Roofline Model Chart**: Interactive Chart.js line plot illustrating arithmetic intensity vs sustained TFLOPS ($418.5\,\text{TFLOPS}$ sustained throughput).
- **Proving Terminal (`TerminalWindow.jsx`)**:
  - Live color-coded terminal log with timestamped event logging, syntax highlighting for crash dumps, and one-click log clearing.

### 6.3 Stage 02: 132-SM Die Topology & 32-Warp Matrix
*Deep microarchitectural visualization showing the physical reality of GPU execution.*
- **Hopper GH100 Silicon Die Floorplan (`HopperDieTopology.jsx`)**:
  - Exact layout of **132 Streaming Multiprocessors** organized into 8 Graphics Processing Clusters (GPCs).
  - Flanked by 4 active HBM3e memory channels representing the $3.35\,\text{TB/s}$ memory highway.
  - Central 50MB High-Speed L2 Cache Crossbar with animated laser pulse indicating data transactions.
  - **Fault Beacon**: During `SANDBOX_FAIL`, SM 14 pulses with high-intensity crimson strobe (`CRITICAL: SM 14 MMU PAGE TRAP`), indicating an unaligned out-of-bounds memory load. Upon blue synthesis, SM 14 transitions to emerald (`ZERO-PENALTY PREDICATION`).
  - **Interactive SM Inspection**: Clicking any SM core displays its local warp scheduler allocation, SRAM partition ($228\,\text{KB}$), and register occupancy ($65,536 \times 32$-bit registers).
- **SIMT Warp 0 Matrix Inspector (`WarpVisualizer.jsx`)**:
  - **32 Individual Hardware Thread Lanes** (Lane 0 through Lane 31) representing lockstep execution of Warp 0.
  - **Interactive Dual-Mode Switcher**: Allows toggling between `Unprotected CUDA (Crash)` and `Aegis Hardened Triton (Immune)`.
  - **Thread Lane Diagnostics**: Clicking any lane reveals its exact 64-bit virtual memory address (`0x7F4E8244`), vector load instruction (`ld.global.nc.v2.f16`), predicate register value (`@p0 = 1` vs `@p0 = 0`), and register payload.
  - Clearly demonstrates how ragged boundaries cause threads 17–31 to trigger fatal bus exceptions in naive CUDA, while Aegis Triton executes hardware suppression in 0 clock cycles.

### 6.4 Stage 03: AST Diff & PTX Disassembly
*The code-level proof verifying why the kernel is immune to failure.*

  - **Left Pane (Vulnerable CUDA C++)**: Highlights unmasked raw pointer indexing with crimson gutters and interactive inline fault callouts (`💥 FAULT: threadIdx.x >= seq_len causes SIGSEGV 139`).
  - **Right Pane (Hardened Triton Python)**: Highlights `@triton.jit` decorators, block offset arithmetic (`offs_m = pid_m * BLOCK_M + tl.arange(0, BLOCK_M)`), and hardware boundary masking (`tl.load(ptr, mask=mask_m, other=0.0)`).

  - One-click toggle switches the view from high-level Python/C++ to low-level NVIDIA PTX ISA assembly.
  - Unmasks the exact Hopper assembly instruction:

  - Proves to NVIDIA compiler judges that Triton generates zero-overhead hardware predication that executes in 0 additional clock cycles.
