# Aegis-Kernel UI-UX Architecture & Design System

## Executive Summary & Design Thesis

Aegis-Kernel is an autonomous GPU invariant and kernel proving workbench engineered for the Nebius x NVIDIA Global AI Hackathon '26. The platform demonstrates a closed-loop adversarial race: **Nemotron Red Adversary** fuzzer generating pathological memory and numerical exploits versus **Nemotron Blue Triton** synthesis engine hardening tensor kernels for NVIDIA Hopper H100 (SM_90a) and Blackwell B200 (SM_100) microarchitectures.

The goal of this UI-UX architecture is to move past conventional hackathon dashboards and generic dark themes. By combining physical supercomputing aesthetics, authentic hardware telemetry, and an uncluttered spatial structure, Aegis-Kernel provides a command interface worthy of high-performance computing (HPC) research environments.

```
+---------------------------------------------------------------------------------------------------+
|                                      EXECUTIVE COMMAND STRIP                                      |
|  [Logo & Mission]   [Workload Selector]   [Sequence Scrubber]   [Hardware Target]   [Attestation] |
+---------------------------------------------------------------------------------------------------+
|                                  SPATIAL PROVING WORKBENCH                                        |
|  [01: Autonomous Combat Arena]    --> Adversarial Fuzzing vs Kernel Synthesis                     |
|  [02: Silicon Topology & Warps]   --> 132-SM Die Matrix & SIMT Predication Map                    |
|  [03: Kernel AST & PTX Diff]      --> Vulnerable CUDA vs Hardened Triton Assembly                 |
|  [04: Microarchitecture Telemetry]--> Memory Hierarchy Waterfall & Nsight HUD                    |
+---------------------------------------------------------------------------------------------------+
|                                      SYSTEM ATTESTATION FOOTER                                    |
|  Cryptographic Invariant Hash | Hardware Predication Verification | Dual-Engine Attestation       |
+---------------------------------------------------------------------------------------------------+
```

## Assumptions & Operating Parameters

To ensure technical rigor while fulfilling all functional goals, the architecture is grounded on the following operational premises:

1. **Microarchitectural Specificity**: Target hardware focuses on the NVIDIA Hopper GH100 architecture (132 Streaming Multiprocessors across 8 GPCs, 60 MB L2 crossbar cache, 228 KB shared memory per SM, 80 GB HBM3e at 3.35 TB/s, and 4th Generation Tensor Cores). Architectural variants (Blackwell B200, Lovelace L40S) scale SM counts, cache dimensions, and memory bandwidth parameters dynamically.
2. **Workload Targets**: Demonstrations evaluate three real-world kernel stress points:
   - `swiglu`: Fused SwiGLU activation with ragged sequence alignment tripping out-of-bounds page faults (`SIGSEGV 139`).
   - `rmsnorm`: Unaligned root-mean-square normalization generating silent data corruption (`SDC`).
   - `softmax`: Online Softmax under high dynamic range triggering exponential overflow (`NaN/Inf`).
3. **Execution Model**: Proving routines execute asynchronously via Server-Sent Events (SSE) spanning five discrete pipeline stages: `TAVILY_RECON`, `RED_ATTACK`, `SANDBOX_FAIL`, `BLUE_SYNTHESIS`, and `DUAL_VERIFY`.
4. **Layout Constraints**: The interface must fit a standard high-definition viewport (1080p to 4K) without mutual component clipping, horizontal overflow, or vertical content collisions.

## Architectural Principles & Spatial System

To solve visual congestion without sacrificing density or technical depth, the system implements four fundamental spatial rules:

### 1. The Principle of Progressive Cognitive Disclosure
Rather than cramming the red/blue adversary timeline, 132 SM silicon grid, 32 SIMT warp registers, PTX assembly diffs, Nsight profiling counters, and memory waterfalls onto one continuous page, the workbench is segmented into **four dedicated operational views**. Each view focuses on a specific dimension of the kernel verification problem:

- **Stage 01: Autonomous Combat Arena**: Closed-loop duel between Red Adversary and Blue Healer, accompanied by speedup delta benchmarks, impact metrics, and raw runtime logs.
- **Stage 02: Silicon Topology & SIMT Warp Matrix**: High-resolution 132-SM core die layout coupled to a 32-lane SIMT lockstep register grid showing active hardware predication (`@p0`).
- **Stage 03: Kernel AST & PTX Disassembly**: Direct side-by-side code comparative analysis between unmasked CUDA C++ and hardened Triton Python, down to raw PTX ISA assembly.
- **Stage 04: Microarchitecture Telemetry & Memory Waterfall**: 4-tier dataflow hierarchy (HBM3e -> L2 Crossbar -> SM SRAM -> Tensor Core ALU) with live Nsight performance counters.

### 2. High-Order Visual Hierarchy & Spacing Rhythm
- **Fixed Executive Command Cockpit (Top Strip)**: Acts as the primary anchor. It maintains state (target hardware, active workload, sequence length, live status) and remains persistently accessible without occupying more than 110px of vertical height.
- **Primary Stage Navigator (Workbench Rail)**: Provides immediate switching across the 4 stages with clear active indicators, stage status pills, and acoustic feedback.
- **Spacious Content Well (`max-w-[1580px]`, `gap-16px` to `gap-24px`)**: Ensures cards have substantial breathing margins, 16px internal padding, and structured visual separation.

### 3. Cyber-Physical Supercomputing Visual System
The design system moves away from flat SaaS aesthetics and arbitrary gradients to reflect the physics and architecture of high-performance silicon:

| Token | Hex / Value | Semantic Role |
| :--- | :--- | :--- |

| `--bg-surface` | `rgba(8, 14, 26, 0.82)` | Glassmorphic instrument surface with backdrop blur for depth separation. |

## Detailed Component Specifications

### 1. Executive Command Cockpit (`ExecutiveCommandBar.jsx`)
The command cockpit anchors the platform. It provides hardware selection, workload orchestration, parameter perturbation, and proving loop controls in a unified horizontal control bridge.

```
+-------------------------------------------------------------------------------------------------------+
| [AEGIS-KERNEL]  |  [SwiGLU] [RMSNorm] [Softmax]  |  Seq: [ 1023 tokens ]  |  [Hopper H100 v]  [ENGAGE] |
| Autonomous Prover  LLaMA-3   Qwen-2.5  FlashAttn3    Ragged Tail (Warp % 32 != 0)  80GB SM_90a 3.35TB/s  RUN |
+-------------------------------------------------------------------------------------------------------+
|  [01 Tavily Recon: OK]  -->  [02 Red Fuzzer: FAIL]  -->  [03 Blue Healer: SYNTH]  -->  [04 Dual: VERIFIED]  |
+-------------------------------------------------------------------------------------------------------+
```

#### Key Capabilities:
- **Hardware Architecture Switcher**: Seamlessly toggles between Hopper H100 SXM5 (80GB, SM_90a, 3.35 TB/s), Blackwell B200 (192GB, SM_100, 8.00 TB/s), and Ada Lovelace L40S (48GB, SM_89, 864 GB/s), updating all memory boundaries and SM die topologies.
- **Workload Target Selector**: One-click switching across candidate kernels, exposing expected vulnerability profiles (e.g., `SIGSEGV 139`, `Silent SDC`, `NaN Overflow`) and target speedup targets.
- **Dynamic Sequence Length Scrubber**: Interactive slider ranging from 256 to 4096 tokens. When set to ragged non-power-of-two boundaries (e.g., 1023 tokens), the cockpit highlights the unaligned tail warp (`1023 % 32 = 31`), visually signaling why boundary predication is mathematically required.
- **Proving Pipeline Milestone Strip**: Step-by-step telemetry tracker reporting execution progression from internet-scale Tavily reconnaissance through formal mathematical attestation.

#### Microarchitectural Features:
- **Full 132-SM Core Interconnect**: Complete interactive die layout partitioned into 8 Graphics Processing Clusters (GPCs). SM 14 dynamically flashes crimson upon Red Agent fault injection and transitions to laser emerald once Triton predication is loaded.
- **HBM3e Memory Highway**: High-bandwidth memory controllers flanking the die, displaying aggregate bus saturation and 3.35 TB/s peak bandwidth potential.
- **32-Thread SIMT Execution Matrix**: Detailed inspection of individual thread lanes (0 through 31) inside Warp 0. Demonstrates how threads exceeding the sequence boundary (`lane_id >= 17`) are clamped using hardware predicate register `@p0 = 0`, bypassing physical bus transactions and writing `0.0` directly into register files without instruction replay penalties.

### 4. Stage 03: Kernel AST Diff & PTX Disassembly (`CodeDiffInspector.jsx`)
Provides side-by-side code comparative analysis for compiler engineers and systems programmers.

- **Vulnerable Baseline (CUDA C++)**: Highlights unmasked raw pointer arithmetic (`in_ptr[token_idx * stride + offset]`) that induces out-of-bounds reads on non-multiple-of-32 token sequences.
- **Hardened Kernel (Triton Python)**: Displays block offset calculations and boundary masks (`mask_m = offs_m < total_ragged_tokens; tl.load(..., mask=mask_m, other=0.0)`).
- **PTX Assembly Mode**: Displays compiled NVIDIA PTX ISA instructions demonstrating predicate assignment (`setp.lt.s32 %p0, %r_offs, %r_limit`) and predicated global loads (`@p0 ld.global.nc.v2.f16 {%r1, %r2}, [%rd3]`), proving zero branch divergence at the machine layer.

### 5. Stage 04: Silicon Memory Waterfall & Nsight HUD (`SiliconMemoryWaterfall.jsx`, `NsightTelemetryHud.jsx`)
Visualizes dataflow velocity and hardware register pressure across the four memory tiers:

1. **Tier 1: Global VRAM (HBM3e)**: 80 GB capacity, 3.35 TB/s bandwidth, ~250 cycles latency. Shows elimination of intermediate tensor round-trips (-42% bus traffic).
2. **Tier 2: L2 Crossbar Cache**: 50 MB capacity, 12.0 TB/s bandwidth, ~35 cycles latency. Displays 94.2% cache hit rate achieved via 128-bit tile coalescing.
3. **Tier 3: SM Shared Memory / SRAM (TMA)**: 228 KB per SM (30 MB total), 33.0 TB/s bandwidth, ~18 cycles latency. Highlights asynchronous Tensor Memory Accelerator (TMA) copies and on-chip activation fusion.
4. **Tier 4: Tensor Core ALU & Register File**: 64K 32-bit registers per SM, 989 TFLOPS peak, 1 cycle latency. Confirms 418.5 TFLOPS sustained throughput with zero register spills.

## Production Polish, Accessibility & Motion Ergonomics

### Layout & Breathing Room Architecture
To eliminate all cramping and visual congestion:
- Global container maximum width is pinned to `1580px`, centered with fluid auto-margins.
- Content elements utilize a two-column responsive grid (`1fr 1fr` or `1.2fr 0.8fr`) with minimum row heights and explicit padding (`p-4` to `p-6`).
- Complex instruments (like the 132-SM grid and 32-thread visualizer) are grouped into paired cards rather than nested arbitrarily.

### Acoustic Feedback & Micro-Interactions
- Built-in sound synthesis engine (`audio.js`) using the browser Web Audio API generates subtle sci-fi clicks, charging tones on collider launch, alert hums during red fault injection, and harmonic resolution chords upon formal invariant attestation.
- Global mute toggle in the command bar allows instant acoustic silence.
- Kinetic hover states, smooth transitions, and glowing indicator dots give interactive life to every hardware node without inducing frame drops.
