# Aegis-Kernel UI-UX Architecture & Design System

## Executive Summary
Aegis-Kernel is an enterprise-grade autonomous GPU invariant and kernel proving workbench engineered for the Nebius × NVIDIA Global AI Hackathon '26. The interface visualizes a closed-loop cyber-physical battle between the **Nemotron Red Adversary** fuzzer and the **Nemotron Blue Triton** autonomous healer across NVIDIA Hopper GH100 and Blackwell B200 hardware.

This architecture eliminates interface congestion through a **4-Stage Spatial Stage Navigator**, paired with high-energy **cyber-physical supercomputer aesthetics** (obsidian void, laser emerald `#00FF88`, plasma coral `#FF0055`, cyan `#00F0FF`, and sub-atomic particle glows). It faithfully reflects low-level silicon architecture: all 132 Hopper Streaming Multiprocessors (SMs), 32-thread SIMT warp execution lanes with hardware `@p0` predication, a 4-tier memory hierarchy waterfall, and real-time Nsight 100KHz micro-telemetry.

---

## 1. Assumptions
1. **Target Hardware**: Primary visualization reflects NVIDIA Hopper GH100 SXM5 (132 SMs across 8 GPCs, 80GB HBM3e at 3.35 TB/s, SM_90a), with selectable targets for NVIDIA Ada Lovelace L40S (SM_89) and NVIDIA Blackwell B200 (192GB HBM3e at 8.0 TB/s, SM_100).
2. **Workload Fixtures**: Workloads benchmark real LLM production kernels: Fused SwiGLU (LLaMA-3/Mistral), Vector RMSNorm (Qwen-2.5/DeepSeek), and Online Softmax (FlashAttention-v3).
3. **Execution Pipeline**: The proving loop streams Server-Sent Events (SSE) through 5 sequential states: `TAVILY_RECON` → `RED_ATTACK_SYNTHESIS` → `SANDBOX_RED_EXECUTE` → `BLUE_SYNTHESIS` → `DUAL_VERIFY` → `COMPLETE`.

## 2. Spatial Workbench Architecture & Decongestion System

### 2.1 The Spatial Staging Model
Rather than stacking all 8 diagnostic instruments into a cramped, single-page viewport (which caused vertical scrolling exhaustion and overlapping HUDs), Aegis-Kernel partitions the workspace into four logically isolated, high-focus proving stages:

### 2.2 Layout & Breathing Room Budget
To guarantee an uncluttered presentation, the interface enforces strict CSS grid constraints:
- **Maximum Content Width**: 1580px centered container with 24px horizontal gutters.
- **Vertical Rhythm**: 16px to 24px component gap, eliminating dense multi-tier margins.
- **Two-Column Pacing**: Dense visualizers (e.g. Hopper Die and Warp Lane Matrix) sit in balanced 50/50 CSS Grid splits (`grid-template-columns: repeat(auto-fit, minmax(580px, 1fr))`) ensuring components never collapse below readable thresholds.
- **Glassmorphism Depth Hierarchy**:
  - `Base Viewport`: `#03060D` Obsidian void with subtle 32px coordinate grid lines.
  - `Instrument Chassis`: `rgba(8, 14, 26, 0.82)` with 16px backdrop blur and 1px emerald/cyan borders.
  - `Raised Focus Element`: `rgba(13, 22, 40, 0.92)` with radial glow accents on active state transitions.

## 4. Hardware Authenticity & Proving Grounds

### 4.1 NVIDIA Hopper GH100 132-SM Die Matrix
- Represents the true GH100 physical silicon floorplan: 8 Graphics Processing Clusters (GPCs), each containing 16 or 18 Streaming Multiprocessors for a total of 132 active SMs.
- Interactive SM selector allows drill-down into any core (e.g. SM 14, where Red attacks target memory boundaries).
- Core color encoding reflects live state: Emerald (Healthy / Hardened), Crimson (OOB Tripped / Page Fault), Amber (High Shared-Memory Contention), Charcoal (Idle / Clock Gated).

### 4.2 32-Thread SIMT Warp Execution Matrix
- Maps the exact 32 physical thread lanes of NVIDIA Warp 0 (Lanes 0 to 31).
- Visualizes `@p0` Hardware Predication:
  - When sequence length is ragged (e.g. `seqLen = 1023`), threads `0..30` compute valid tensor elements (`p0 = true`).
  - Thread 31 attempts an Out-Of-Bounds memory transaction beyond boundary `1023`.
  - In Red unmasked CUDA, Thread 31 emits an unpredicated load resulting in `SIGSEGV (Exit Code 139)`.
  - In Blue Triton, Thread 31's predicate `@p0` evaluates to `0`, dynamically masking the memory transaction without hardware branch divergence penalty.

### 4.3 4-Tier Memory Waterfall Dataflow
Visualizes bandwidth and latency across the true physical silicon memory hierarchy:
1. **Tier 1: HBM3e Memory**: 80 GB capacity, 3.35 TB/s peak bandwidth, ~250ns latency.
2. **Tier 2: 50 MB L2 Cache**: Unified cross-bar cache, 12.0 TB/s bandwidth, ~40ns latency.
3. **Tier 3: 228 KB Shared Memory / L1 (SRAM)**: Per-SM scratchpad, 33.0 TB/s aggregate bandwidth, ~12ns latency.
4. **Tier 4: 4th-Gen Tensor Cores**: 418.5 TFLOPS FP16/BF16 matrix execution engine, sub-nanosecond register file pipeline.

### 4.4 AST Code Diff & PTX ISA Disassembly
Displays synchronized side-by-side code blocks:
- Left: Vulnerable CUDA C++ code with explicit pointer arithmetic missing boundary masks.
- Right: Hardened Python Triton kernel featuring `tl.load(..., mask=mask, other=0.0)`.
- Bottom Pane: Disassembled Hopper PTX Assembly highlighting predication instruction:
  ```ptx
  setp.lt.s32   %p0, %r3, %r4;        // Compare lane offset against boundary
  @%p0 ld.global.nc.f32 %f1, [%rd2];   // Predicated memory load: executes ONLY if %p0 is true
  @!%p0 mov.f32 %f1, 0f00000000;       // Masked lanes zero-initialized
  ```

## 5. Interactive Proving Parameters & Real-Time Scrubber

### 5.1 Dynamic Sequence Length Scrubber
- Range: `1` to `4096` tokens.
- Interactive slider with instant feedback indicating warp boundary alignment:
  - Multiple of 32 (e.g. `1024`, `2048`): Clean aligned warp execution (`tail = 0`).
  - Ragged Boundary (e.g. `1023`, `2047`, `3001`): Triggers **Ragged Warp Alert**, highlighting that threads `seqLen % 32` will trigger an OOB hazard unless hardware predication is synthesized.

### 5.2 Hardware Target Switcher
- Instantly reconfigures telemetry metrics and memory bandwidth specs between:
  1. **NVIDIA Hopper H100 SXM5**: 80GB HBM3e, SM_90a, 132 SMs, 3.35 TB/s.
  2. **NVIDIA Ada Lovelace L40S**: 48GB GDDR6, SM_89, 142 SMs, 864 GB/s.
  3. **NVIDIA Blackwell B200**: 192GB HBM3e, SM_100, 160 SMs, 8.0 TB/s.

### 5.3 Workload Fixture Presets
- Quick-toggle between high-profile LLM operator kernels:
  - **Fused SwiGLU**: Tests feed-forward activation tensor boundaries with ragged tails.
  - **Vector RMSNorm**: Tests reduction warp shuffles and silent data corruption (SDC).
  - **Online Softmax**: FlashAttention-3 running max/sum exponentiation checks.

## 6. Implementation Architecture & Source Code

### 6.1 State Management & Clean Decoupling
The workbench state is decoupled cleanly in React:
- Global Cockpit State: Hardware target, workload preset, sequence length, execution status.
- Stage View Navigation: Zero full-page reloads; CSS transitions ensure smooth 150ms cross-fades without layout shifts.
- Diagnostic Log Stream: Monospaced terminal auto-scrolls with syntax-highlighted stage markers (`[INIT]`, `[TAVILY]`, `[CRIMSON EXPLOIT]`, `[NEMOTRON BLUE]`, `[INVARIANT ATTESTED]`).
