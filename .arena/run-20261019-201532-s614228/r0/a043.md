# Aegis-Kernel UI-UX Architecture & Design System Specification

## 1. System Context & Executive Design Mission
Aegis-Kernel serves as an autonomous GPU invariant and kernel proving workbench engineered for the Nebius x NVIDIA Global AI Hackathon '26. The platform proves the closed-loop battle between Nemotron Red Adversary fuzzer and Nemotron Blue Triton healer across NVIDIA Hopper GH100 (SM_90a) and Blackwell B200 (SM_100) hardware architectures.

Judges evaluating HPC systems demand instant visual validation of deep hardware mechanics, clear operational telemetry, and an uncluttered cockpit that retains high-energy cyber-physical aesthetics without collapsing into congested dashboard sprawl.

## 2. Resolving Architectural Open Questions

Before establishing the design system, every architectural and interaction question left by the baseline is resolved:

### Question 1: Monolithic Workbench vs. Spatial Tab Segmentation
* **Question**: Does segmenting the workbench into distinct tabs prevent cognitive overload, or does it obscure critical cross-instrument correlations (e.g., viewing an SM die fault concurrently with warp lane divergence)?
* **Resolution**: A hybrid spatial architecture. Stage-focused tabs are retained to give primary instruments 100% breathing room (resolving the congestion critique), but a synchronized **Mini-HUD Strip** and global **State Synchronization Bus** persist across tabs so hardware state, fault alerts, and telemetry counters remain visible regardless of view.

### Question 2: Scrubber Mechanics & Real-Time Warp Divergence Mapping
* **Question**: How does dynamic sequence length scrubbing (e.g., tokens 1 to 2048) directly drive visual hardware predication without requiring asynchronous backend round-trips?
* **Resolution**: Deterministic client-side hardware emulation for SIMT warp mechanics. A sequence length of $N = 1023$ tokens partitioned into 32-thread warps calculates:
  $$\text{Active Threads} = 1023 \pmod{32} = 31$$
  Thread lanes 0 through 30 evaluate to True (`@p0`), executing vector load instructions, while Thread Lane 31 evaluates to False (`!@p0`), triggering active hardware predication or OOB memory traps.

### Question 3: Aesthetics vs. Readability Under Extended Inspection
* **Question**: How do we produce glowing supercomputer visuals ("GA-GA" factor) without degrading typography legibility or creating visual fatigue?
* **Resolution**: Strict tokenized luminance boundaries. Surface backdrops remain anchored to true Obsidian Void (`#03060D`) with glass opacity between 82% and 88%. High-luminance emitters (NVIDIA Laser Emerald `#00FF88`, Plasma Coral `#FF0055`, Cyber Cyan `#00F0FF`) are reserved strictly for active hardware states, data buses, and fault indicators, accompanied by bounded CSS drop shadows ($0\;0\;18\text{px}$).

## 3. Concrete Worked Example: Fused SwiGLU at Ragged Sequence Length 1023

To anchor every UI component, state transition, and visual element in physical reality, we trace one full proving lifecycle end to end with exact hardware values.

### Scenario Parameters:
* **Target Architecture**: NVIDIA Hopper GH100 SXM5 (80GB HBM3e, 132 SMs, 3.35 TB/s peak bandwidth, SM_90a compute capability).
* **Workload**: Fused SwiGLU Operator ($\text{SwiGLU}(x) = (xW \cdot \text{sigmoid}(xW)) \cdot xV$).
* **Dynamic Scrubber Position**: Sequence length $N = 1023$ tokens (ragged boundary, $1023 \not\equiv 0 \pmod{32}$).
* **Hardware Trigger**: Thread Lane 31 in Warp 0 on SM 14 attempts unmasked vector memory access.

### End-to-End Execution Trace:

1. **Step 1: Invariant Initialization & Target Armed (`IDLE` $\to$ `INIT`)**
   * **Cockpit State**: Scrubber set to $1023$; hardware target locked to Hopper H100.
   * **Visual Representation**: The 132-SM die displays a quiescent emerald pulse ($1.2\text{s}$ breathing period). Warp Visualizer shows all 32 lanes staged in ready status.
   * **Telemetry Baseline**: SM Occupancy 0%, Memory Bandwidth 0.00 TB/s, Tensor Utilization 0.0%.

2. **Step 2: Tavily Recon & PTX Hardware Contract (`TAVILY_RECON`)**
   * **Telemetry Query**: Autonomous verification of Hopper SM_90a memory alignment constraints.
   * **Visual State**: A cyber cyan scanning ray sweeps across the executive command bar. Terminal emits:
     `[TAVILY ORACLE] Verified 128-bit vector alignment & PTX ISA specs for Hopper SM_90a.`
   * **Memory Model**: 16-byte alignment invariant enforced for global memory vectorization (`ld.global.v4.u32`).

3. **Step 3: Crimson Adversary Fuzzing Attack (`RED_ATTACK` $\to$ `SANDBOX_FAIL`)**
   * **Adversary Action**: Nemotron Red synthesizes an unmasked CUDA C++ kernel omitting tail-predication guards for boundary threads:
     `int idx = blockDim.x * blockIdx.x + threadIdx.x; out[idx] = swiglu(in[idx]);`
   * **Hardware Collision**: Thread Lane 31 ($idx = 1023$) attempts to fetch beyond allocated buffer boundary ($1023 \ge 1023$ under 0-indexed float4 alignment).
   * **Visual State**: SM 14 on the Hopper Die flashes into Crimson Coral (`#FF0055`) with a $24\text{px}$ high-energy bloom. The 32-Warp Matrix highlights Lane 31 in violent pulse:
     `TRIPPED: OOB Read at 0x7F89B200. Exit Code 139 (SIGSEGV).`
   * **Memory Waterfall Impact**: Global Memory tier flashes red; L2 Cache reports uncoalesced memory abort; Tensor Cores stall at 0 TFLOPS.

4. **Step 4: Nemotron Blue Triton Healing Synthesis (`BLUE_SYNTHESIS`)**
   * **Healer Action**: Nemotron Blue synthesizes a hardened OpenAI Triton kernel introducing explicit `@p0` hardware masks:
     `mask = (offs_m[:, None] < seq_len) & (offs_n[None, :] < d_model)`
     `tl.load(ptr + offs, mask=mask, other=0.0)`
   * **Visual State**: Code Diff Inspector illuminates additions in emerald green (`#00FF88`). PTX disassembly displays the synthesized hardware predicate:
     `@p0 ld.global.nc.v4.u32 {r1, r2, r3, r4}, [addr];`
   * **Warp Matrix Transformation**: Thread Lane 31 switches to masked-safe state (`!@p0` indicator active), showing safe zero-fill bypass without hardware fault.

5. **Step 5: Dual Verification & Hardware Benchmarking (`VERIFYING` $\to$ `COMPLETE`)**
   * **Performance Delta**:
     * Unhardened Baseline: $0.0\text{ TFLOPS}$ (Crashed via SIGSEGV).
     * Hardened Triton Kernel: $418.5\text{ TFLOPS}$ ($42.3\%$ of peak Hopper FP16 tensor core throughput).
     * Achieved Bandwidth: $2.84\text{ TB/s}$ ($84.8\%$ of physical $3.35\text{ TB/s}$ HBM3e peak).
     * Measured Speedup: $\mathbf{2.35\times}$ over baseline fallback kernel.
   * **Attestation Certificate**: SHA-256 formal invariant attestation generated: `0x7f56b9fe02089399`. Modal trigger armed for instant cryptographic audit.

## 6. Detailed Component Architecture

### 6.1 Executive Command Cockpit (`ExecutiveCommandBar.jsx`)
* **Hardware Target Selector**: Switch seamlessly between **NVIDIA Hopper H100 SXM5** ($80\text{GB}, \text{SM\_90a}, 3.35\text{ TB/s}$), **Ada Lovelace L40S** ($48\text{GB}, \text{SM\_89}$), and **Blackwell B200** ($192\text{GB}, \text{SM\_100}, 8.0\text{ TB/s}$).
* **Workload Selection Tabs**: One-click toggling between canonical LLM operator workloads:
  1. `swiglu`: Fused SwiGLU (LLaMA-3 / Mistral), tripping SIGSEGV 139 under ragged boundaries.
  2. `rmsnorm`: Vector RMSNorm (Qwen-2.5 / DeepSeek), tripping silent data corruption (SDC).
  3. `softmax`: Online Softmax (FlashAttention-v3), tripping numerical NaN overflow.
* **Dynamic Sequence Length Scrubber**: Range slider ($1$ to $2048$ tokens) with visual real-time badge:
  * Green badge when cleanly divisible by 32: `ALIGNED (32n)`.
  * Solar Amber warning when ragged: `RAGGED BOUNDARY (Tail: X / 32 threads active)`.
* **Proving Collider Action Button**: Primary CTA with dual-state animated pulse, loading spinners, and audio cue triggers.

### 6.2 Stage 01: Red vs Blue Arena & Impact Delta (`RedBlueArena.jsx`, `MicDropDelta.jsx`)
* **Adversary Red Collider**: Visualizes Nemotron Red fuzzer emitting malicious tensor permutations designed to breach boundary invariants.
* **Healer Blue Collider**: Visualizes Nemotron Blue Triton engine synthesizing AST transforms, injecting masked block pointers, and restoring kernel stability.
* **Executive Speedup Delta**: High-impact typographic metric display comparing unoptimized kernel performance ($0.0\text{ TFLOPS}$) with hardened Triton execution ($418.5\text{ TFLOPS}$, $2.35\times$ speedup).
* **Formal Verification Certificate**: Cryptographic attestation seal with copyable SHA-256 hash and direct trigger for the Attestation Audit Modal.

### 6.3 Stage 02: 132-SM Hopper Die & 32-Warp Matrix (`HopperDieTopology.jsx`, `WarpVisualizer.jsx`)
* **Hopper GH100 Full Die Representation**: Authentically renders all 132 Streaming Multiprocessors arranged across 8 Graphics Processing Clusters (GPCs).
  * Quiescent SMs: Subtly glowing dark emerald borders.
  * Active Computing SMs: Bright emerald reactor pulse.
  * Fault Tripped SM: SM 14 flashes violent crimson coral on fuzzer attack.
  * Interactive Click-to-Inspect: Clicking any SM updates the telemetry inspector to that SM's local cache and warp scheduler.
* **32-Thread SIMT Warp Visualizer**:
  * Individual rendering of all 32 thread lanes ($L_0$ to $L_{31}$).
  * Visual status flags for Thread ID, Register Allocation, Predicate Register `@p0`, and Memory Address Offset.
  * Clear visual differentiation for Lane 31: Unmasked OOB memory crash during Red attack, transitioning to safely masked bypass under Blue Triton healing.

### 6.4 Stage 03: Code Diff & PTX Disassembly (`CodeDiffInspector.jsx`)
* **Side-by-Side Unified Diff**:
  * Left pane: Fragile CUDA C++ kernel highlighting missing boundary checks in crimson.
  * Right pane: Hardened OpenAI Triton Python kernel highlighting `@p0` predication and vectorized tensor blocks in emerald.
* **Hopper PTX ISA Disassembly**: Direct hardware-level inspection of compiled NVIDIA PTX instructions:
  * Displays `@p0 ld.global.nc.v4.u32` predication.
  * Registers tracking ($%r0-%r31$, $%p0$, $%rd0$).

### 6.5 Stage 04: Nsight Telemetry & 4-Tier Memory Waterfall (`NsightTelemetryHud.jsx`, `SiliconMemoryWaterfall.jsx`)
* **Nsight Telemetry HUD**:
  * Real-time 100KHz sampling metrics: Tensor Core Active Cycles, Warp Execution Efficiency ($98.4\%$), L1/Shared Memory Hit Rate ($94.2\%$), and DRAM Bandwidth Saturation ($84.8\%$).
* **Silicon Memory Waterfall**:
  * Visualizes physical four-tier memory hierarchy:
    1. **HBM3e Global Memory**: $80\text{GB} \cdot 3.35\text{ TB/s}$.
    2. **L2 Unified Cache**: $50\text{MB} \cdot 12.0\text{ TB/s}$.
    3. **SM SRAM / Shared Memory**: $228\text{KB per SM} \cdot 33.0\text{ TB/s}$.
    4. **Tensor Core Registers**: 4th-Gen Hopper Matrix Units ($1000\text{ TFLOPS FP16}$).
  * Dynamic animated particles representing dataflow rate flowing through memory tiers into computation units.
