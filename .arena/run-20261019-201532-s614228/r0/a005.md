# Aegis-Kernel UI-UX Architecture & Design System Specification

## Executive Architecture & Design System Overview
**Aegis-Kernel** is an autonomous GPU invariant and kernel proving workbench engineered for the Nebius × NVIDIA Global AI Hackathon '26. The platform demonstrates a closed-loop combat loop: Nemotron-3-Ultra Red Adversary fuzzer versus Nemotron-70B Blue Triton healer running on NVIDIA Hopper GH100 SXM5 and Blackwell B200 hardware.

The UI-UX architecture eliminates dashboard congestion and information crowding through a **4-Stage Spatial Workbench Architecture** paired with an **Executive Cockpit Command Bar**. This layout provides breathing room, clear visual hierarchy, authentic silicon-level physical telemetry, and high-energy cyber-physical aesthetics.

---

## Assumptions & Design Constraints
1. **Target Hardware Context**: NVIDIA Hopper GH100 (132 SMs, 8 GPCs, 50MB L2 crossbar, 80GB HBM3e @ 3.35 TB/s) and Blackwell B200 (160 SMs, 8.0 TB/s HBM3e).
2. **Evaluation Viewport**: 1440p / 1080p desktop displays without vertical scroll cramping or element overlap.
3. **Information Density Rule**: Maximum of 2 to 3 primary visual instruments per spatial stage, maintaining a 1580px max-width container with 20px spatial grid gutters.
4. **Zero-Warning Production Standard**: Vite build and React/Tailwind frontend with zero runtime errors, zero compilation warnings, and strict architectural fidelity.

## Spatial Layout & Workbench Decomposition

### 1. Master Executive Command Cockpit (`ExecutiveCommandBar.jsx`)
- **Persistent Global Header**: Positioned as a sticky top cockpit (`z-index: 80`) with backdrop blur (`blur(24px)`) and subtle emerald rim lighting (`rgba(0, 255, 136, 0.15)`).
- **Brand Lockup & Target Selector**: Includes quick-switch dropdown for silicon targets:
  - `NVIDIA Hopper H100 SXM5` (80GB · SM_90a · 3.35 TB/s)
  - `NVIDIA Ada Lovelace L40S` (48GB · SM_89 · 864 GB/s)
  - `NVIDIA Blackwell B200` (192GB · SM_100 · 8.0 TB/s)
- **Workload Operator Switcher**: One-click switching between `Fused SwiGLU` (LLaMA-3 / Mistral), `Vector RMSNorm` (Qwen-2.5 / DeepSeek), and `Online Softmax` (FlashAttention-v3).
- **Dynamic Tensor Stress Scrubber**: 128 to 2048 token dynamic scrubber with instant ragged boundary detection badge (`Tail: N/32 Lanes Trapped` vs `128-bit Coalesced`).
- **5-Stage Laser Stepper Pipeline**: Real-time reactive stepper showing `01 Tavily Recon` ➔ `02 Red Fuzzer` ➔ `03 Sandbox Crash` ➔ `04 Nemotron Blue` ➔ `05 Dual Invariant`.

### 2. Stage 01: Red vs Blue Collider & Mic-Drop Delta
- **`RedBlueArena.jsx`**: Dual-wing combat layout. Crimson wing (Nemotron-3-Ultra) showing illegal memory offsets and SIGSEGV 139 stack traces vs Emerald wing (Nemotron-70B Triton) showing `@p0` hardware predication and formal invariant guarantees. A central spinning dual-ring collision reactor visualizes live kernel synthesis.
- **`MicDropDelta.jsx` & `VerificationImpact.jsx`**: Side-by-side verification impact instruments contrasting 2.35x execution speedup, memory bandwidth liberation (-42% DRAM bus traffic), and cryptographic attestation hash (`0x7f56b9fe02089399`).
- **`TerminalWindow.jsx`**: Live SSE execution log stream with high-contrast color-coded tags (`[CRIMSON EXPLOIT]`, `[TAVILY ORACLE]`, `[NEMOTRON BLUE]`, `[FORMAL INVARIANT ATTESTATION]`).

### 3. Stage 02: 132-SM Die Topology & 32-Warp Matrix
- **`HopperDieTopology.jsx`**: 132 individual Streaming Multiprocessor (SM) cores rendered in an 8-GPC physical die floorplan. Clicking any SM focuses real-time core telemetry. SM 14 dynamically lights up in flashing crimson during OOB memory violations and switches to emerald upon Triton kernel healing. Central crossbar represents the 50MB L2 cache highway (3.35 TB/s).
- **`WarpVisualizer.jsx`**: 32 individual SIMT thread lanes (T0 to T31) for Warp 0. Interactive thread inspector allows inspecting thread virtual memory addresses, `@p0` predicate register status, PTX instructions, and SRAM register values. Features an instant toggle between "Unprotected CUDA (Crash)" and "Aegis Hardened Triton (Immune)".
- **`NsightTelemetryHud.jsx`**: Real-time 100KHz telemetry HUD monitoring SM occupancy (100%), Tensor Core saturation (418.5 TFLOPS), HBM3e bus saturation (2.84 TB/s), SRAM allocation (184 KB / 228 KB), zero warp divergence (0.0%), and zero register spills (32 regs/thread).

### 4. Stage 03: Semantic AST Diff & PTX Disassembly
- **`CodeDiffInspector.jsx`**: Side-by-side semantic inspection comparing raw CUDA C++ (unmasked raw pointer access) with hardened Triton Python (`tl.load(..., mask=mask, other=0.0)`).
- **Hopper PTX Assembly ISA View**: Instant toggle revealing low-level PTX code targeting Hopper SM_90a:
  - Vulnerable: `ld.global.v2.f16 {%r1, %r2}, [%rd_in + %r3];` (bus panic)
  - Hardened: `@p0 ld.global.nc.v2.f16 {%r1, %r2}, [%rd_in + %r3];` (zero-overhead hardware predicate mask)
- **`TerminalWindow.jsx`**: Monospaced terminal console underneath for deep diagnostic traces.

### 5. Stage 04: Nsight Profiler & Silicon Memory Waterfall
- **`NsightTelemetryHud.jsx`**: Full-width hardware instrumentation grid.
- **`SiliconMemoryWaterfall.jsx`**: 4-tier hardware dataflow waterfall mapping latency and memory traffic:
  - **Tier 1: Global VRAM (HBM3e)**: 80 GB · 3.35 TB/s · ~250 Cycles (3x unfused round-trips reduced to 1x streamed transfer, -42% bus traffic).
  - **Tier 2: L2 Crossbar Cache**: 50 MB · 12.0 TB/s · ~35 Cycles (94.2% L2 hit rate via 128-bit tile coalescing).
  - **Tier 3: SM Shared Memory / SRAM (TMA)**: 228 KB/SM · 33.0 TB/s · ~18 Cycles (activations fused in SRAM registers).
  - **Tier 4: Tensor Core ALU & Register File**: 64K registers · 989 TFLOPS Peak · 1 Cycle (sustained 418.5 TFLOPS throughput, 99.4% warp efficiency).
- **`VerificationImpact.jsx`**: Formal verification attestation with SHA-256 invariant hash export and GitHub PR generator modal.
