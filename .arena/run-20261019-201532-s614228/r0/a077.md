# Aegis-Kernel UI-UX Architecture & Design System

## Executive Summary & System Overview

**Aegis-Kernel** is an autonomous GPU invariant and kernel proving workbench engineered for the **Nebius x NVIDIA Global AI Hackathon '26**. The system orchestrates a closed-loop adversarial proving cycle between **Nemotron-3-Ultra (Red Adversary)** and **Nemotron-3-70B-Triton (Blue Healer)** targeting **NVIDIA Hopper GH100** and **Blackwell B200** hardware.

This architecture delivers a Tier-1 HPC visualization platform that completely resolves workspace congestion while elevating the visual design to rival NVIDIA's in-house silicon bring-up and Nsight systems. It implements a **4-Stage Spatial Proving Workbench**, an **Interactive Execution Cockpit**, an **Executive Matrix HUD**, and a **Reactive Audio-Visual Hardware Telemetry Pipeline**.

## 2. Design System Tokens: Cyber-Physical Quantum Supercomputer

The aesthetic rejects generic SaaS dashboards and simplistic black/white themes, drawing direct lineage from high-performance computing consoles and clean-room diagnostic instruments.

### 2.1 Color Palette & Radiation Emissives
* **Deep Obsidian Void (`#03060D`)**: Primary backdrop absorbing light, minimizing eye fatigue during prolonged kernel verification sessions.
* **Elevated Silicon Glass (`rgba(8, 14, 26, 0.85)`)**: Sub-surface container panels featuring backdrop blur (`backdrop-filter: blur(24px)`) and subtle emerald border highlights (`rgba(0, 255, 136, 0.14)`).
* **NVIDIA Laser Emerald (`#00FF88` / `rgba(0, 255, 136, 0.45)`)**: Primary signal of verified invariants, healthy SM lanes, and Triton synthesis efficiency.
* **Nemotron Plasma Coral (`#FF0055` / `rgba(255, 0, 85, 0.50)`)**: Adversarial fuzzing exploits, out-of-bounds (OOB) memory breaches, and hardware trap traps.
* **Quantum Neon Cyan (`#00F0FF` / `rgba(0, 240, 255, 0.40)`)**: Interconnect bus telemetry, NVLink-4 packet flow, and PTX instruction predication markers.
* **Amber Warning Flash (`#FFB800` / `rgba(255, 184, 0, 0.40)`)**: Warp execution divergence, L2 cache bank conflict warnings, and tensor core stall indicators.

### 2.2 Typography Scale
* **Display / UI System**: `Plus Jakarta Sans` (Weights: 500, 600, 700, 800) with tight tracking (`-0.02em`) for crisp, legible cockpit readouts.
* **Code / Hardware ISA Telemetry**: `JetBrains Mono` (Weights: 400, 500, 700) with tabular figures for register dumps, hexadecimal addresses, and PTX disassembly.

## 3. Detailed Component Implementations & Hardware Authenticity

### 3.1 Executive Command Cockpit (`ExecutiveCommandBar.jsx`)
The cockpit anchors the top view, allowing real-time parameter changes without shifting workspace elements:
* **Hardware Target Switcher**: Toggles between `NVIDIA Hopper H100 SXM5` (80GB HBM3, 132 SMs, 3.35 TB/s) and `NVIDIA Blackwell B200` (192GB HBM3e, 160 SMs, 8.0 TB/s), dynamically updating clock cycles and memory thresholds.
* **Workload Presets**: Instant selection across canonical LLM kernels: `swiglu`, `flash_attention_v2`, `layernorm_fused`, and `gemm_fp8`.
* **Dynamic Sequence Length Scrubber**: Range scrubber (128 to 8,192 tokens) that triggers live vector boundary recalculations. Non-power-of-two values (e.g., 1023) surface unaligned memory access patterns.
* **Collider Action Control**: Dual-state initiation button with reactor pulse animation and progress synchronization.

### 3.2 Stage 01: Red vs Blue Proving Collider (`RedBlueArena.jsx`, `MicDropDelta.jsx`)
* **Adversarial Battleground**: Real-time duel visualization. Red Nemotron probes unaligned vector strides while Blue Nemotron generates memory masks and vector clamps.
* **Throughput Delta HUD**: Highlights the transition from unhardened baseline to stabilized kernel:
  * Latency: `1.42 ms` reduced to `0.61 ms` (**2.35x speedup**).
  * Arithmetic Intensity: `148.2 TFLOPS` increased to `418.5 TFLOPS`.
  * Invariant Status: 100% formal safety attestation (`0x7f56b9fe02089399`).

### 3.3 Stage 02: 132-SM Die Topology & 32-Warp Matrix (`HopperDieTopology.jsx`, `WarpVisualizer.jsx`)
* **Hopper GH100 Die Map**: Authentic representation of 132 Streaming Multiprocessors arranged across 12 Graphics Processing Clusters (GPCs).
  * Interactive SM Core Inspector: Hovering or clicking SM 14 reveals its internal status (active fuzzer exploit point vs patched Triton block).
  * Micro-thermal mapping: SM tiles dynamically transition from cool emerald to crimson heat maps when handling boundary edge cases.
* **32-Lane SIMT Warp Matrix**: Displays all 32 hardware threads in Warp 0.
  * Thread Lane Predication: Displays individual lane active masks (`0xFFFFFFFF` full divergence vs predicated lanes `@p0`).
  * Visual Divergence Indicator: Threads 0-30 show active execution while Thread 31 displays the boundary clamp preventing memory faults.

### 3.4 Stage 03: Compiler AST Diff & PTX Disassembly (`CodeDiffInspector.jsx`)
* **Side-by-Side Verification Diff**: Left pane displays vulnerable unmasked CUDA C++ kernel; right pane displays hardened Triton Python kernel with explicit tile boundary masking (`tl.load(..., mask=offsets < n_elements)`).
* **PTX ISA Disassembly**: Direct visualization of Hopper assembly instructions showing `@p0 ld.global.v4.u32` predication flags that eliminate runtime bounds-checking overhead.

### 3.5 Stage 04: Nsight Profiler & 4-Tier Memory Waterfall (`NsightTelemetryHud.jsx`, `SiliconMemoryWaterfall.jsx`)
* **Nsight 100KHz Telemetry**: Live metric meters tracking Tensor Core Utilization (94.2%), Memory Bandwidth (2.84 TB/s), Warp Execution Efficiency (98.4%), and L2 Hit Rate (89.1%).
* **Silicon Memory Waterfall**: An animated tier-by-tier hardware dataflow:
  1. `HBM3e / VRAM` (80GB at 3.35 TB/s)
  2. `50MB Crossbar L2 Cache` (Bank conflict resolution)
  3. `228KB Distributed Shared Memory (SRAM / TMA Async)`
  4. `4th-Gen Hopper Tensor Cores` (FP8 / FP16 Tensor Engine)
