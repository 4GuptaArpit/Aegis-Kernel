ATTACK 1 [FATAL] Hardcoded Localhost SSE URL Breaks Multi-Host and Production Execution Environments
Where: `frontend/src/App.jsx` lines 142-144: `const eventSource = new EventSource(\`http://localhost:8000/api/v1/execute/${selectedFixture}?hardware_target=${encodeURIComponent(selectedHardware)}\`);`
Problem: Hardcoding `http://localhost:8000` directly violates production deployment standards and breaks whenever Aegis-Kernel runs on remote Nebius cloud instances, preview domains, Docker containers, or reverse proxies. If the frontend is hosted on any non-local hostname or port (e.g. `https://aegis.nebius.ai` or Vite dev server on port 5173 connecting via proxy), the browser throws Cross-Origin / Mixed-Content network errors and fails to connect to the SSE endpoint entirely. It must use relative URL paths (`/api/v1/execute/...`) or environment variables (`import.meta.env.VITE_API_URL`).

ATTACK 2 [FATAL] State Desynchronization Between Sequence Length Scrubber and Execution Collider Pipeline
Where: `frontend/src/App.jsx` lines 105 & 142-144: `const [seqLen, setSeqLen] = useState(1023);` and `EventSource(\`http://localhost:8000/api/v1/execute/${selectedFixture}?hardware_target=${encodeURIComponent(selectedHardware)}\`)`
Problem: The task explicitly requires an "Interactive Proving Ground: Must allow interactive parameter adjustment (dynamic sequence length scrubber, hardware target switcher, workload presets) and live execution proving loops." In a097's implementation, the user adjusts the `seqLen` slider, triggering `onSeqLenChange`, but `seqLen` is completely omitted from the `EventSource` query parameters (`?hardware_target=...` only). Changing the slider has zero functional effect on the backend execution run, decoupling the dynamic parameter scrubber from the proving loop.

ATTACK 3 [MAJOR] Warp Boundary Calculations Fail and Invert Semantics on Valid Ragged Tails
Where: `frontend/src/components/WarpVisualizer.jsx` lines 612 & 628: `const boundaryLimit = isSwiglu ? 17 : (isRmsnorm ? 24 : 20);` and `const isValid = selectedLane < boundaryLimit;`
Problem: In GPU microarchitecture, if `seq_len = 1023`, `seq_len % 32 = 31`, meaning 31 threads (T0–T30) are valid in-bounds loads and only thread T31 is out-of-bounds. However, `WarpVisualizer` hardcodes arbitrary static boundaries (`17` for swiglu, `24` for rmsnorm) completely detached from the user's `seqLen` state (which isn't even passed into `WarpVisualizer`). Furthermore, under `boundaryLimit = 17`, thread lane T17 is classified as `isValid = false` (out-of-bounds/predicated), while lines 609-640 describe lane 17 as an active memory fault. This arbitrary hardcoding ignores actual SIMT boundary math.

ATTACK 5 [MAJOR] Missing Offline Simulation Fallback When SSE Backend Is Disconnected
Where: `frontend/src/App.jsx` lines 190-193: `eventSource.onerror = () => { setIsRunning(false); eventSource.close(); };` and Section 2 Assumption 3: "...with robust client-side simulation fallbacks when disconnected."
Problem: a097 explicitly claims in Section 2 Assumption 3 that it provides "robust client-side simulation fallbacks when disconnected." In actual code, when `eventSource.onerror` fires (which occurs immediately if no backend server is running on `http://localhost:8000`), the handler silently sets `isRunning` to false and closes the connection without running any simulation fallback, leaving the UI completely frozen with empty state, no proving data, and no feedback to the user.
