ATTACK 2 [MAJOR] Misrepresented Mathematical Predication and Tail Thread Invariant
Where: `a089.md` Section 2 (Q3), lines 56-59
Problem: Section 2 claims: "When $N = 1023$, $1023 \pmod{32} = 31$, leaving Lane 31 vulnerable. The visualizer illustrates how Triton generates `@p0` hardware predication: $\text{Predicate Register: } @p0 = (i < \text{seq\_len})$". This is mathematically and architecturally incorrect for SIMT execution. A sequence length of 1023 across 32-thread warps means the last warp processes elements 992 to 1023. Element index 1023 corresponds to local lane offset $1023 - 992 = 31$. Therefore, Lane 31 has index $1023$, which is $< 1024$ and within the 1023 valid elements ($0 \dots 1022$ are 1023 elements, so element 1023 is the first out-of-bounds element). More crucially, the underlying component `WarpVisualizer.jsx` explicitly hardcodes `boundaryLimit = 17` for `swiglu`, where lanes 17 through 31 are out-of-bounds. Claiming only Lane 31 is vulnerable directly contradicts both the codebase logic and real ragged SIMT boundary divergence.
