ATTACK 1 [FATAL] Hardcoded 32-Warp Boundary Limit Flattens Valid Tail Tokens to Zero
Where: `frontend/src/components/WarpVisualizer.jsx`, Line 542: `const boundaryLimit = seqLen % 32 || 32;`
Problem: The task explicitly requires an interactive parameter adjustment with dynamic sequence length scrubber (e.g. sequence lengths up to 4096 tokens) to authentically represent SIMT 32-thread warps and ragged tail bounds. In a GPU grid, Warp 0 handles linear thread indices 0 to 31. When `seqLen` is a multiple of 32 (such as standard block boundaries `seqLen = 128, 256, 512, 1024, 2048`), `seqLen % 32` evaluates to `0`. Because JavaScript evaluates `0 || 32` to `32`, it masks the bug for multiples, but whenever `seqLen < 32` or any arbitrary global sequence offset is rendered, `boundaryLimit` calculates the tail remainder of the entire sequence instead of the warp's slice. More critically, if a user sets `seqLen = 0` (or `seqLen % 32 === 0` in dynamic block slicing), the modulo operator produces `0`. Furthermore, in hostile scenario 1 (line 64), the author claims: `seq_len = 1023, 1025 ... Boundary limit computed via seqLen % 32 || 32; thread lanes 0–30 marked valid, lane 31 dynamically marked predicated`. But for `seq_len = 1025`, `1025 % 32 = 1`. In Warp 0 (which processes tokens 0 through 31, all of which are strictly `< 1025`), setting `boundaryLimit = 1` incorrectly marks 31 fully valid active tokens (lanes 1 through 31) as out-of-bounds predicated faults in Warp 0. Global sequence length `seqLen` cannot be mapped directly into Warp 0 with `seqLen % 32` without accounting for warp ID or total valid tokens in Warp 0.

ATTACK 4 [MINOR] Static Thread Inspector Selection Desynchronizes From Hardware Fault Lane
Where: `frontend/src/components/WarpVisualizer.jsx`, lines 539 and 556-573
Problem: Requirement 4 specifies authentic representation of SIMT 32-thread warps and `@p0` hardware predication. In `WarpVisualizer`, the default inspection state is hardcoded to `const [selectedLane, setSelectedLane] = useState(17)`. However, when `seqLen = 1023` (the default initial state in `App.jsx`), `boundaryLimit = 1023 % 32 = 31`. The component fails to automatically select or highlight the actual faulting lane (lane 31) when an exploit stage (`SANDBOX_FAIL` / `RED_ATTACK`) occurs, forcing the user to manually guess which lane failed.
