ATTACK 3 [MAJOR] Dynamic Sequence Length Scrubber Ragged Boundary Calculation Produces Inverted Masking
Where: Section 3 "Second-Order State Feedback Loops", line 51 of `a080.md`:
"Modifying `seqLen` directly recalculates `seqLen % 32`. If ragged (`remainder != 0`), Warp 0 marks tail lanes with `@p0 = 0` (suppressed)..."
Problem: Logic error on hardware SIMT predication. If `seqLen` is 1023 (as initialized in line 161), `1023 % 32 = 31`. In GPU SIMT execution, the first 31 threads (lanes 0 to 30) are active and in-bounds (`@p0 = 1`), while only lane 31 is the tail lane that needs suppression (`@p0 = 0`). If the code simply checks `remainder != 0` without applying the partition threshold `lane_id >= (seqLen % 32)`, evaluating tail lanes naively or inverting the predicate masks will either suppress active lanes or execute invalid memory access on the tail lane, causing an unhandled hardware memory violation.
