ATTACK 1 [FATAL] WarpVisualizer Prop Breakage Prevents Dynamic Sequence Length Scrubber Interaction
Where: Lines 286-290 in `frontend/src/App.jsx`:
```jsx
<WarpVisualizer 
  selectedFixture={selectedFixture} 
  isRunning={isRunning} 
  currentStage={currentStage} 
/>
```
Problem: The task explicitly requires Requirement 5: "Must allow interactive parameter adjustment (dynamic sequence length scrubber, hardware target switcher, workload presets) and live execution proving loops." Furthermore, Section 6.2 claims WarpVisualizer "Reflects unaligned sequence lengths (e.g. seqLen = 1023, tail boundary at Lane 17)". However, in a030's implementation of `App.jsx`, `seqLen` is maintained in App state (`const [seqLen, setSeqLen] = useState(1023)`) and passed to `ExecutiveCommandBar`, but it is completely omitted from `<WarpVisualizer />` props. As a result, adjusting the sequence length scrubber in the UI has zero effect on the WarpVisualizer component; thread lanes cannot react or reflect tail boundary conditions when the user scrubs `seqLen`.
