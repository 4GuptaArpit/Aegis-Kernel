ATTACK 1 [FATAL] WarpVisualizer ignores the dynamic sequence length scrubber and hardcodes boundary limits
Where: `frontend/src/components/WarpVisualizer.jsx:12` and a088 section 2 "Stage 02: 132-SM Die & 32-Warp Execution Matrix: When ragged sequence length (seqLen % 32 != 0) is applied, tail lanes display hardware divergence and predication masking in real time."
Problem: Requirement 5 states "Must allow interactive parameter adjustment (dynamic sequence length scrubber, hardware target switcher, workload presets) and live execution proving loops." In `App.jsx`, `seqLen` is managed by `ExecutiveCommandBar`'s scrubber slider, but `WarpVisualizer` is invoked as `<WarpVisualizer selectedFixture={selectedFixture} isRunning={isRunning} currentStage={currentStage} />` without receiving `seqLen`. Inside `WarpVisualizer.jsx:12`, it hardcodes: `const boundaryLimit = isSwiglu ? 17 : (isRmsnorm ? 24 : 20);`. When the user scrubs `seqLen` to any value (e.g., `1023`, where `1023 % 32 = 31` threads should be valid and only Thread 31 is ragged/masked), `WarpVisualizer` completely fails to respond, remaining static at 17 lanes. The claim that the dynamic sequence scrubber updates warp tail lane predication in real-time is false and broken in the implementation.

ATTACK 3 [MAJOR] Broken SSE EventSource execution lifecycle in browser environment
Where: `frontend/src/App.jsx:57-59` and a088 section 4.3 "EventSource SSE vs. Bi-Directional WebSocket: Server-Sent Events (EventSource) for live proving pipeline feeds."
Problem: The code connects via `new EventSource('http://localhost:8000/api/v1/execute/${selectedFixture}?hardware_target=${encodeURIComponent(selectedHardware)}')`. However, the execution loop does not pass `seqLen` to the backend endpoint, meaning the fuzzer never receives the scrubbed sequence length. Furthermore, if the backend server is unreachable or errors out during proving (`eventSource.onerror`), `App.jsx:105-108` simply closes the stream and sets `isRunning: false` without updating `currentStage` or surfacing any user-facing error message or toast in the UI. The user is left in an indefinite frozen state with no indication of what failed.
