```jsx
<WarpVisualizer selectedFixture={selectedFixture} isRunning={isRunning} currentStage={currentStage} />
```
Problem: The task explicitly requires "Hardware Target Switcher" and authentic representation of "NVIDIA Hopper H100 and Blackwell B200 hardware". While `App.jsx` tracks `selectedHardware` and passes it to `ExecutiveCommandBar`, it completely omits passing `selectedHardware` to `HopperDieTopology` and `WarpVisualizer`. Furthermore, `HopperDieTopology.jsx` hardcodes `const TOTAL_SMS = 132;` with zero prop definition or logic for `selectedHardware`. When the user selects "NVIDIA Blackwell B200", the die topology remains locked to 132 SMs instead of rendering the 160 SM Blackwell configuration, and WarpVisualizer is incapable of reflecting SM_100 architectural properties. The hardware switching control is a disconnected cosmetic dummy for the silicon inspector.

ATTACK 3 [MAJOR] Non-integer SM core grid breaks orthogonal 132-core die layout into ragged dangling row
Where: In Section 4 `Essential CSS Structural Overrides (frontend/src/index.css)`:
```css
.holographic-sm-grid {
  display: grid;
  grid-template-columns: repeat(12, minmax(0, 1fr));
  gap: 4px;
```
Problem: The task explicitly requires hardware authenticity representing "NVIDIA Hopper GH100 architecture (132 Streaming Multiprocessors... organized across 8 GPCs)". In GH100 silicon, 132 SMs are organized across symmetrical GPCs. A grid of `repeat(12, minmax(0, 1fr))` results in $132 / 12 = 11$ full rows. However, a 12-column layout fails to represent the physical 8-GPC dual-hemisphere architecture (which maps to symmetric 22-column structures with crossbars). More critically, on medium and responsive viewport widths, 12 fractional columns with `gap: 4px` inside a 7-column layout (`xl:col-span-7`) forces core cells to squish below readable text size for core labels (`font-size: 9px`), producing visual clipping and layout collapse.
