ATTACK 3 [MAJOR] Floorplan Division Logic Calculates Invalid GPC Clusters Exceeding Hopper Hardware Specifications
Where: `frontend/src/components/HopperDieTopology.jsx` lines 756 & 788
Problem: The GH100 floorplan calculation derives the GPC index using `Math.floor(idx / 17)`. For SM indices 119 through 131 (e.g. SM 131), `Math.floor(131 / 17) = 7`, but for indices such as SM 132 or if scaled to 160 SMs, it overflows. More critically, NVIDIA Hopper GH100 contains exactly 8 GPCs with up to 18 SMs per GPC (or 16-18 SMs in production SXM5 configurations: 8 GPCs × 16/18 SMs = 132/144 SMs). Dividing by 17 creates irregular clustering where GPC-7 holds only 13 SMs (119 to 131) while GPCs 0-6 hold 17 SMs, misrepresenting real NVIDIA TPC/GPC paired layout architecture and breaking hardware authenticity.
