ATTACK 3 [MAJOR] SIMT WarpVisualizer hardcodes non-sensical tail thread math disconnected from sequence length and tile size
Where: `frontend/src/components/WarpVisualizer.jsx` line 467: `const isOobLane = laneId >= 28 && (seqLen % 32 !== 0);`
Problem: Hardware SIMT warps execute 32 threads in lockstep. If a ragged sequence length has an unaligned tail `seqLen % 32 !== 0`, the out-of-bounds lanes are exactly those where `laneId >= (seqLen % 32)`. For example, if `seqLen = 1025`, `1025 % 32 = 1`, so lanes 1 through 31 are out-of-bounds! Hardcoding `laneId >= 28` arbitrarily assumes exactly 4 lanes are masked regardless of whether `seqLen % 32` is 1, 13, 21, or 31. This is physically and mathematically false for NVIDIA Hopper SIMT execution, violating Requirement 4 ("Hardware Authenticity: Must authentically represent NVIDIA Hopper GH100 architecture (SIMT 32-thread warps, @p0 hardware predication)").
