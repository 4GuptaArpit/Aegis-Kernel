ATTACK 4 [MAJOR] Missing mathematical definition and hardware implementation for ragged boundary masking
Where: Section 2 Question 2 Resolution: "Active Threads = 1023 (mod 32) = 31... Thread lanes 0 through 30 evaluate to True (@p0), executing vector load instructions, while Thread Lane 31 evaluates to False (!@p0)"
Problem: The mathematical formula given is flawed and ambiguous for general sequence length boundaries. If sequence length is 1024 (cleanly divisible by 32), the formula evaluates to $1024 \pmod{32} = 0$, which according to this logic would mean 0 active threads rather than all 32 active threads in the final block/warp. Moreover, in Section 3 Step 3, the opponent states: "idx = 1023 attempts to fetch beyond allocated buffer boundary (1023 >= 1023 under 0-indexed float4 alignment)". In 0-indexed buffers of length 1023 tokens, index 1023 is indeed out-of-bounds, but vector float4 loading requires addressing byte boundaries $(idx \times 4 \times \text{sizeof(float)})$, which the specification completely glosses over without defining how thread lane coordinates map to uncoalesced global memory addresses.
