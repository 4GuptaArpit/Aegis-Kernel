ATTACK 5 [MINOR] Fractional arithmetic in GPC and TPC calculation causes fractional cluster IDs
Where: `frontend/src/components/HopperDieTopology.jsx` (lines 675-676 in a051.md):
```javascript
gpc: Math.floor(i / 16.5),
tpc: Math.floor((i % 16.5) / 2)
```
Problem: Calculating GPC and TPC indices using floating-point divisor `16.5` produces irregular, non-integer cluster distributions. In Hopper GH100, Streaming Multiprocessors are grouped symmetrically into Texture Processing Clusters (2 SMs per TPC, up to 9 TPCs per GPC). Dividing by `16.5` results in fractional modulus math `(i % 16.5)` that miscalculates physical TPC cluster assignment for multiple SMs, corrupting the tooltip metadata displayed to NVIDIA judges (`title={\`SM ${sm.id} (GPC ${sm.gpc}, TPC ${sm.tpc})\`}`).
