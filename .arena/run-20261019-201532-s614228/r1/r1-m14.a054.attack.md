ATTACK 1 [FATAL] Client-side simulation fallback claimed in Section 3 is completely unimplemented in App.jsx
Where: Section 3, constraint 2: "Real-time telemetry streams over Server-Sent Events (SSE) via `http://localhost:8000/api/v1/execute/{fixture_id}?hardware_target={target}` with automatic fallback to high-fidelity deterministic client simulation when disconnected." vs App.jsx lines 166-218.
Problem: App.jsx initializes an EventSource directly against `http://localhost:8000/api/v1/execute/...` and on error provides only `eventSource.onerror = () => { setIsRunning(false); eventSource.close(); };`. There is no mock generator, timer, or deterministic simulation loop anywhere in `handleLaunchProvingGround`. When executed in any standalone frontend testing, grading, or disconnected hackathon demo environment without a running FastAPI backend on port 8000, clicking "Launch Proving Ground" aborts instantly with zero output, logs, or metrics, breaking Requirement 5 ("Interactive Proving Ground: Must allow interactive parameter adjustment... and live execution proving loops").

ATTACK 2 [FATAL] Dynamic sequence length scrubber fails to connect to backend execution or simulation
Where: App.jsx lines 166-168:
```jsx
const eventSource = new EventSource(
  `http://localhost:8000/api/v1/execute/${selectedFixture}?hardware_target=${encodeURIComponent(selectedHardware)}`
);
```
and Section 2.2 item 1: "integrating the Dynamic Sequence Length Scrubber directly into the proving loop, allowing instant injection of pathological ragged tensors (seq_len mod 32 != 0) to trigger real-time kernel resynthesis."
Problem: The SSE URL query parameters omit `seqLen` entirely. Changing the dynamic sequence length slider updates local state `seqLen` and writes a transient text string to logs, but does not send the sequence length to the execution endpoint, nor does it pass `seqLen` down to any child visualizer (`HopperDieTopology`, `WarpVisualizer`, or `SiliconMemoryWaterfall`). Requirement 5 explicitly dictates an "interactive parameter adjustment (dynamic sequence length scrubber...)", yet adjusting the scrubber has zero functional effect on proving execution, bounds calculations, or hardware warp states.
